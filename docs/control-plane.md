# Control plane (`src/control-plane`)

Summary in [CLAUDE.md](../CLAUDE.md).

## Stack and conventions

- Fastify 5 + `fastify-type-provider-zod` (zod 4), PostgreSQL via **Drizzle** (`drizzle-orm` + `pg`). Schema in `src/db/schema.ts`; plain SQL migrations from `drizzle-kit generate` into `drizzle/`, committed (the Rust gateway reads the same tables with its own SQL); never edit applied migrations; additive only.
- DTOs are zod schemas in `src/dto` (**no shared package**; the UI copies what it needs, keep in sync by hand). Every route validates params/body/response and is in OpenAPI; **Swagger UI at `/api/docs`** (`/api/docs/json`), Authorize signs in through Dex (code + PKCE, public client `splitcortex-ui`, whose Dex `redirectURIs` must include `<web app origin>/api/docs/static/oauth2-redirect.html` in every environment; a pasted bearer token works too). Validation messages are i18n keys. **Error messages are translated server-side** (`src/i18n/messages.ts`, en + ro): routes throw `app.httpErrors.x('errors.someKey')` (values for `{{placeholders}}` via `withParams`), and `plugins/i18n.ts` translates by the request's `Accept-Language` (English fallback, `Content-Language` on the answer). Add every new key to both catalogues (a test checks parity). The UI and all nodes send `Accept-Language`.
- Routes live under `/api` (ingress does not strip it; served on the web app host and web node host, same origin, no CORS). Probes `/healthz` (liveness) and `/readyz` (DB) at the root.
- **Auth**: `Authorization: Bearer <Dex token>` verified with `jose` against the Dex JWKS (issuer = `dex.config.issuer`, audience `splitcortex-ui`; JWKS URL defaults to the in-cluster Dex service, no public TLS needed). **No users table**: identity comes from token claims (`GET /api/me`); memberships reference the lowercased email as text. Tenant checks via `requireOrgRole` (non-members get 404).
- Tests: route tests against the real migrations on in-process Postgres (**PGlite**, `src/test/harness.ts`).
- Config changes: `recordConfigChange` inside the transaction, `notifyConfigChange` after commit (gateway feed, see [gateway.md](gateway.md)).

## Entities and API

- **Orgs / members / pools**: organisations (get/update/delete; delete owner-only and records a config change per cascaded pool), memberships (owner/admin/member; list/add by email/change role/remove or leave), pools (get/update/delete, serving/balancing type; DTO has `onlineNodes` = approved, connected, `node_status` < 60 s old, and `totalNodes` = approved nodes). Roles: owners manage everyone; admins manage only plain `member`s and can't grant higher roles; anyone may leave; the **last owner can't be demoted or removed** (owner rows locked `FOR UPDATE`). Deleting a pool/org records `node` changes so the gateway closes sockets.
- **Account deletion** (`DELETE /api/me`, `routes/me.ts`): there is no users table and Dex is never touched, so deleting an account removes the caller's memberships, deletes their pending enrollment codes and anonymises `created_by` (`deleted`) on API keys and benchmarks they created. **Refused with 409 (`errors.accountOwnsOrgs`) while the caller is the only owner of any organisation** (even one with no other members): they must transfer ownership or delete the org first. They can sign in again afterwards and start fresh. The web app offers it in the user menu (confirm dialog, then signs out).
- **Metrics**: `pool_metrics` and `node_metrics` (written by the gateway only, see docs/gateway.md; `org_id` FK with cascade, no prompts or keys). `GET /api/organisations/:orgId/metrics` (any member): `from`/`to` (default last hour, max 7 days), `step` `1m|5m|15m|1h` (default: smallest keeping ~240 points), optional `poolId` and `nodeId`; returns `pools` (usage requests/errors/tokens joined in, refused counts, peak in-flight, p50/p95 latency and time to first token as the upper bound of the histogram bucket holding the percentile) and `nodes` (averages per step; lowest battery, highest temperature, in-flight = average of the per-minute totals; `requests`/`failures` and `measuredTokensPerSec` = total generated tokens / total generation time, all measured by the gateway, as opposed to `tokensPerSec` which the device reports). Always scoped by organisation. Retention: CronJob `control-plane-metrics-prune` (`controlPlane.metricsPrune.*`, **7 days default**, hourly; `src/db/metrics-prune-cli.ts`).
- **Audit log**: `audit_logs` (`org_id` FK with cascade, `source` control_plane|gateway, actor type/id, dotted `action`, entity, `outcome` success|denied|failed, ip, jsonb `metadata`). `plugins/audit.ts` records every mutation under `/organisations` from one table of rules (`onSend` hook: success on 2xx, `denied` on 403; non-members get 404 and are **not** logged so the log never reveals that an organisation exists; written right after the response, not in the handler's transaction; a failed write is logged and never turns the request into a 500). A mutating route missing from the table (`RULES`, or `NOT_AUDITED` with a reason) fails app start-up, so new endpoints must decide. PATCH bodies are stored as `metadata.changes` (no secrets in them). `node.enroll` is written inside the enrollment transaction (`db/audit.ts` `recordAudit`). `GET /api/organisations/:orgId/audit-logs/export` (admin or owner) downloads the same filtered log (without paging) as `format=csv` (default) or `json`, streamed in keyset batches of 1000 so memory stays flat; CSV cells that start with `= + - @` are prefixed with `'` against spreadsheet formula injection; reading is not audited. `GET /api/organisations/:orgId/audit-logs` (admin or owner): filters `action` (exact or prefix ending in `.`), `actor`, `outcome`, `source`, `from`/`to`; newest first, keyset cursor (microsecond timestamp + id), `limit` ≤ 100. Retention: CronJob `control-plane-audit-prune` (`controlPlane.auditPrune.*`, 90 days, daily; `src/db/audit-prune-cli.ts`). Deleting an organisation deletes its rows (so `DELETE /organisations/:orgId` is not audited).
- **Usage**: `usage_records` + `usage_flushes` are **written by the gateway only** (`pool_id`/`key_id` have no FKs so history outlives deletions). `GET /api/organisations/:orgId/usage` (any member; `from`/`to` max 92 days, `granularity` hour|day, `groupBy` pool|key|model, `poolId`/`model` filters).
- **Nodes** (`nodes`): created **only by enrollment** (no manual create). List per pool, view, approve/rename, revoke. Per-device overrides via `PATCH /organisations/:orgId/nodes/:nodeId` (admin only, recorded as a `node` config change so the gateway pushes `NodeConfig`): `computeBackend` cpu|gpu|null, `maxContextTokens` 512..131072|null, `keepScreenOn`, `enableMtp` (null = device decides). `node_status` (cpu/memory/battery/temperature/in-flight/tokens-per-sec, actual `backend`/`max_context_tokens`, `modalities` (comma separated `image`/`audio`, exposed as `live.modalities`), `gateway_id`, `gateway_keys`) is **written by the gateway only**; a node is online only while `connected` AND the row is < 60 s old; stale telemetry isn't shown. `GET /api/node/me` (device-authenticated, approved only) returns name, org (name, slug), pool, approval; the sealed enrollment response carries `orgName`/`poolName`.
- **API keys** (`api_keys`, `api_key_pools`; `routes/api-keys.ts`): admin/owner only; `GET/POST /organisations/:orgId/api-keys`, `DELETE .../:keyId` (soft revoke, idempotent). Token `sc_` + 32 random bytes base64url, shown once; stored: `sha256(token)` hex + a 10-char display prefix. Optional expiry (set on create, changeable later with `PATCH .../api-keys/:keyId` `{expiresAt}`: a future time, or `null` for never; a revoked key answers 409; an expired key works again once extended), `created_by`, `last_used_at` (gateway writes), `revoked_at`. Create/revoke/pool delete/org delete record an `api_key` change; the gateway checks `revoked_at`/`expires_at` itself.
- **Limits**: nullable `limit_requests_per_minute`, `limit_tokens_per_minute`, `limit_tokens_per_day` on organisations and api_keys (DTO `limits`, `src/dto/limits.ts`, `src/limits.ts`; bounds 1..10^7 / 10^9 / 10^12). `PATCH /organisations/:orgId` takes partial `limits` (null clears one; `{}` rejected); keys take `limits` on create and `PATCH .../api-keys/:keyId`; each records a config change.
- **Remote restart**: `POST /api/organisations/:orgId/nodes/:nodeId/restart` (admin or owner, `202 {id}`; `409 errors.nodeOffline` unless the node is online; audited `node.restart`). It inserts a `node_commands` row (migration 0014) and sends `NOTIFY node_commands`; the gateway instance holding the node claims it and delivers it (docs/gateway.md). Nothing is queued for an offline node.
- **Benchmarks** (`routes/benchmarks.ts`): `GET/POST /organisations/:orgId/pools/:poolId/benchmarks`, `DELETE .../:benchmarkId` (admins create/delete, members read; pool must serve a **chat** model (an embedding pool answers 409), ≥1 node online, none started in the last 5 min; newest 10 kept). Status derives from per-node results the gateways fill in (`gateway_instances`, `benchmarks`, `benchmark_results`; migration 0007).
- **Model kind** (`models.kind`, migration 0014): `chat` (default) or `embedding`, chosen when the model is added (`from-url` and `uploads` bodies take `kind`) and returned in `ModelDto` and `GET /api/node/models`. An embedding model (EmbeddingGemma-style `.litertlm`) is served at `/v1/embeddings`; give it a pool of its own.
- **Models**: see below. **One model per pool**: `pool_models.pool_id` unique; `PUT /organisations/:orgId/pools/:poolId/models/:modelId` replaces it; the list returns at most one.

## Models and object storage

- Org-scoped (`models`, `pool_models`; unique name per org; only `.litertlm`, max 32 GiB). Files in an S3-compatible bucket on **Garage** (single node, `garage` Helm subchart 2.5.0 from `https://charts.derwitt.dev`, image overridden to multi-arch `dxflrs/garage`, replication 1; random credentials in Secret `garage-credentials`: `rpcSecret`, `token`, `access-key`, `secret-key`; the subchart installs a ClusterRole for its discovery CRD). **Garage is internal only: no ingress, no public S3, no CORS.** Without S3 config the model endpoints answer 503.
- **Job `garage-bootstrap`** (control plane image, `storage/bootstrap-cli.ts`; plain Job on first install, retries ~10 min; `post-upgrade` hook afterwards; plain Job under Tilt that the control plane depends on) configures Garage via the admin API (`garage-admin:3903`): layout, ImportKey, bucket, AllowBucketKey; idempotent. Only this Job holds the admin token.
- **Uploads stream through the control plane, never buffered**: `POST /models/uploads` → `{model, partSize, partCount}` (8 MiB parts, larger for huge files to stay under 10,000); browser `PUT`s each part (`application/octet-stream`, Content-Length = expected size) to `/models/:id/parts/:n` (piped into S3 `UploadPart`, returns ETag); `POST /models/:id/complete` verifies size (mismatch deletes and fails). Small parts because Traefik's 60 s request read timeout applies to each (no entryPoint timeout changes).
- **Hugging Face URLs** are mirrored once by an in-process worker (`models/mirror.ts`; DB-claimed `FOR UPDATE SKIP LOCKED`, stale claims recovered after 2 min, progress heartbeat doubles as cancellation): only `https` on `huggingface.co`/`*.hf.co`, redirects followed manually and re-checked per hop (SSRF), optional `HF_TOKEN` sent to `huggingface.co` only, sha256 computed while streaming, size checked. Nodes never talk to Hugging Face.
- **Node downloads (decided, built)**: directly from the control plane, never via the gateway or object storage. `GET /api/node/models` lists ready models of the node's pool (`id, name, kind, fileName, sizeBytes, sha256`); `GET /api/node/models/:modelId/file` streams it (`Accept-Ranges`, single `Range` per request for resume, `206`/`416`, `X-Content-SHA256`/`ETag`; the node verifies). Anything not ready or not in the node's pool = generic 404.
- **Device auth** (`plugins/node-auth.ts`): `Authorization: Node <nodeId>.<unixSeconds>.<signature>`, Ed25519 by the enrolled key over `splitcortex-node-request-v1\nMETHOD\npath\nunixSeconds` (path as received without query, including `/api`); skew ≤ 60 s; unapproved/deleted nodes fail; every failure is the same 401; no secret sent; replay possible only for the same method+path within the skew.
- **Sweep**: CronJob `control-plane-sweep` (chart `controlPlane.sweep`: schedule, `maxAgeHours` default 24; `storage/sweep.ts`, entry `storage/sweep-cli.ts`) deletes models still `uploading` past the max age (config change recorded, multipart aborted) and aborts orphan multipart uploads older than that (not owned by any model or mirror). A single upload longer than the max age is cut off.

## Migrations

`controlPlane.migrate` runs `dist/db/migrate.js`: first install as a plain Job (a post-install hook would deadlock: hooks wait for ready workloads, which crash-loop without a schema); upgrades as a `pre-upgrade` hook Job (retries while Postgres is down). Tilt: plain Job `control-plane-migrate` that `control-plane` depends on (dev image runs it with `tsx`); new migration files aren't live-synced, so Tilt rebuilds the image and recreates the Job.
