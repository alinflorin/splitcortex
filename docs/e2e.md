# End-to-end suite

Rules: [CLAUDE.md](../CLAUDE.md). Code in `src/e2e` (pnpm, Playwright, TS).

## What it does

One run (`workers: 4`, `E2E_WORKERS`) against one environment (`BASE_URL`, default `https://local.splitcortex.com`; Dex `dex.<host>`, web node `web-node.<host>`). **`setup` first; then `api`, `ui`, `tenancy`, `nodes-web`, `nodes-cli`, `nodes-multi`, `nodes-android` in parallel** (specs in a project keep order); `cleanup` last. **`perf` runs separately and last** (CI: only if everything else passed). Safe because each node type has its own pools and API key.

1. **setup**: signs in every `E2E_EMAILS`/`E2E_PASSWORDS` user via Dex (`.auth/`), then as user 1 **finds or creates** org `e2e`, two fixed Hugging Face models (chat SmolLM2-135M-Instruct, embedding EmbeddingGemma 300M), one pool each, and waits until `ready`. Org, models, pools **persist between runs**; per run it clears leftover devices and creates a fresh API key.
2. **nodes** (`nodes-web|cli|android.spec.ts`; no emulator = Android skipped): each type has its own `e2e-chat-<type>` and `e2e-embeddings-<type>` pools and a key **scoped to those two** (the gateway resolves pool from `model`, so a shared name must not be reachable from two pools). The node enrolls by typed code, comes online, serves via Playground and `/v1` (JSON, SSE, bad key 401; embeddings), then device page, usage/metrics, audit, **engine overrides**, **benchmark** (chat only), **remote restart**, revoke. `E2E_NODE_TYPES` (`web,cli,android` or `none`) limits types. Code in `lib/nodeSuite.ts`, `lib/drivers/`.
   - **web**: second browser context on `web-node.<host>` (Chromium with WebGPU/SwiftShader flags).
   - **cli**: released `splitcortex-node` (`cli-node-latest` or `E2E_CLI_VERSION`) cached in `.cache/` by `lib/releases.ts` (refetched when the published sha256 changes, since the rolling asset keeps its name); `join --url --code`, then `run` as a child with a throw-away `SPLITCORTEX_HOME`.
   - **android**: released APK (`mobile-node-latest` or `E2E_MOBILE_VERSION`) on the adb emulator; `splitcortex://enroll` deep link, uiautomator taps (`lib/adb.ts`); for `local.splitcortex.com` runs `adb reverse tcp:443 tcp:443`.
3. **nodes-multi** (`lib/cliNodes.ts`; throw-away pools/keys in `e2e`). **CLI nodes run `run --fake`** (`new CliNode()` default; `new CliNode(false)` = real engine). Nodes answer instantly (`QUICK`: 1 ms); the shared pair `n1`/`n2` use `STEADY` (20 ms, 200 tok/s) so mid-answer tests (device dying/stopping, client hanging up) catch the stream. Real engine stays in `nodes-cli` and the few cases that need it (embedding meaning, model landing in `--models-dir`). A released CLI older than `--fake` fails on the unknown flag. Covers: load sharing and weighted balancing under concurrency (only 200/429/503 with `Retry-After`), every balancing type, real telemetry, killed/frozen (`SIGSTOP`)/cut (`SIGKILL`/`SIGTERM`) devices, restart of an offline device (409), device setting vs admin override, the device API signed with the node's key (`nodeAuthHeader`: all bad variants one 401; `Range` 206/416; other pool's model 404), single-use codes, revocation, approval, token limit (`429`), replacing a pool's model under a device, CLI + web in one pool, client hang-up frees the device, `finish_reason: length`, usage sums, non-ASCII, stream shape, oversize prompt (`400 context_length_exceeded`, also ro), embeddings on a real device (order, size, `dimensions`, base64 = float, `task`, meaning), removing a model/pool under a live device, bulk codes, admin overrides, CLI commands (`status`, `config --models-dir`, `update --check`, `leave`). `E2E_NODE_TYPES=none` in CI.
4. **api** (`control-plane.spec.ts`, `gateway.spec.ts`, `api-security.spec.ts`, `api-edge`; throw-away orgs/pools): token checks, `/me`, orgs, pools, enrollment codes, usage/metrics shapes, members/roles (needs user 2), audit, org delete, en/ro errors; keys, expiry/limits (org limits shared by all keys; started early in the minute so the window can't roll), auth errors, `/v1/models` scoping, `503` without a device, `429`, gateway audit rows (polled, batched), embeddings/chat/media validation edges. `api-security`: code dies after 3 guesses with the same generic 404, cross-org isolation at gateway and control plane, scoped keys can't reach a third pool (404), a flood leaves a few audit rows, model life cycle. The per-IP `/enroll/*` limit (30/min) runs only with `E2E_RATE_LIMIT=1` (it would break node projects' enrollments for a minute).
5. **ui** (`ui.spec.ts`, `ui-admin`, `ui-app`, `ui-org`, `web-node.spec.ts`; throw-away org): every org page, pool lifecycle, members, plain-member view, Romanian, Playground, models (**tiny file upload** into Garage), keys, audit, usage/metrics, settings, signed-out flows, Home/About/downloads (menu links via `menuLink` in `lib/ui.ts`; public pages also have footer links), phone layout, and a sweep of every page in en and ro for untranslated keys and script errors. `seo.spec`: what a crawler sees without JS, robots/sitemap/`X-Robots-Tag` per environment (local/stg closed, prd open), `noindex` on app/Dex/web node/`/api`, real 404s, no redirect hops, language/URL sync. `analytics.spec`: no banner/requests where no id (local, stg); where one is (prd), banner first, nothing before Accept, choice remembered (Google blocked).
6. **approval** (in `nodes-web`): approval pool, pending web node, admin approves.
7. **tenancy**: user 2 can't read or delete user 1's org.
8. **cleanup** (setup's teardown, runs after failures): revokes the run's devices and key. Nodes enroll afresh every run and re-download the model.
9. **perf** (`perf.spec.ts`, `lib/perf.ts`; `--project=perf --workers=1`): performance of **our code, not a model or the runner**, from a client on the runner against stg. Throw-away `least_in_flight` pool with a **fleet of fake CLI nodes** (`firstTokenMs: 20, tokensPerSec: 100`; `PERF_NODES` default 12, one enrolled every 6 s because `/enroll/*` allows 30 calls/min per address and a device uses two). Measures platform overhead, streams (TTFT, token gaps), concurrency up to and beyond one stream per device (served or refused 429/503, none hung), cheap paths, a device killed under load (failover, reconnect), control plane p50/p95, metering lag. Assertions only for correctness under load (exact `tok0 tok1 …`, refusal kinds, nothing hung, failover <15 s); **timings are reported, not asserted** (`perf-results/results.json`, `summary.md`, compared with the previous successful run: ⚠ = p95 >2x + 25 ms; `PERF_ENFORCE=1` fails on it). Client event-loop lag is recorded to tell client-bound from slow platform. Needs a released CLI node with `--fake`.

**Known gaps**: code expiry after 10 min; gateway drain/multi-instance; model change mid-download; foreground-only behaviour of web/Android nodes; multimodal on a real device (only the gateway's 400s); a successful Hugging Face import beyond setup; resume after a gateway restart.

## Running

- Local: `cp .env.example .env`, fill `E2E_EMAILS`/`E2E_PASSWORDS` (users from `chart/values-local.yaml`), `pnpm install`, `pnpm install:browsers`, `pnpm test` (`test:ui` for Playwright UI; headed locally, headless in CI). Per-IP limit test, run alone: `E2E_RATE_LIMIT=1 pnpm exec playwright test --project=setup --project=api -g "limit calls per IP"`. Start the emulator first or Android is skipped.
- CI `e2e.yaml`: daily 03:17 UTC and manual (`cli_version`, `mobile_version`) against stg, environment `stg` (secrets `E2E_EMAILS`, `E2E_PASSWORDS`). `prepare` runs `--project=setup` once (no creation race), then a parallel matrix: **platform** (`api`, `ui`, `tenancy`), **web**, **cli**, **multi node**, **android** (KVM + emulator, API 34 x86_64), each with its own `E2E_NODE_TYPES` and `e2e-report-<name>` artifact (HTML, traces, `reports/junit.xml`); then **perf** (`needs: e2e` succeeded; `perf_nodes` input; downloads the last successful run's `perf-results` as baseline, appends `summary.md` to the job summary, uploads `perf-results` for 30 days). Caches: pnpm, browsers, release downloads, AVD snapshot.
- **Users in stg**: chart value `e2e.users` (`{email, hash}`) is appended to Dex `staticPasswords` by `dex-config.yaml`; empty in git, `deploy.yaml` (stg only) bcrypts the secrets with `htpasswd`. Local users live in git-ignored `values-local.yaml`.

## Gotchas

- **GitHub rate limit**: `lib/releases.ts` uses the GitHub API; anonymous = 60/h per address, so CI jobs pass `GITHUB_TOKEN: ${{ github.token }}`; set it locally too. On failure the newest `.cache/` copy is used.
- `AddModelDialog` and confirm dialogs are `alertdialog`, others `dialog`. A Fluent toast renders its text twice: `.first()`. Wait for closed dialogs with `dialogsClosed(page)` (`lib/ui.ts`).
- "Start" matches "Restart": `exact: true`.
- `cliNodeBinary()` unpacks each release once into `.cache/<tag>/`; never unpack over a running executable.
