# End-to-end suite

Rules: [CLAUDE.md](../CLAUDE.md). Code in `src/e2e` (own pnpm project, Playwright, TypeScript).

## What it does

One run (`workers: 4`, `E2E_WORKERS`) against one environment (`BASE_URL`, default `https://local.splitcortex.com`; Dex is `dex.<host>`, web node `web-node.<host>`). **`setup` runs first; then `api`, `ui`, `tenancy`, `nodes-web`, `nodes-cli`, `nodes-multi`, `nodes-android` in parallel** (specs in one project keep their order); `cleanup` last. **`perf` is run separately and last** (CI: only when every other job passed; see 9). Safe because every node type has its own pools and API key.

1. **setup**: signs in every `E2E_EMAILS`/`E2E_PASSWORDS` user through Dex (`.auth/`), then as user 1 **finds or creates** the org `e2e`, the two fixed models from Hugging Face (chat SmolLM2-135M-Instruct, embedding EmbeddingGemma 300M), one pool each, and waits until the models are `ready`. Org, models and pools **persist between runs**. Per run it clears leftover devices and creates a fresh API key.
2. **nodes** (`nodes-web|cli|android.spec.ts`; a missing emulator skips Android): each type has its own `e2e-chat-<type>` and `e2e-embeddings-<type>` pools and a key **scoped to those two pools** (the gateway resolves the pool from `model`, so a shared name must not be reachable from two pools). In each pool the node enrolls by typed code, comes online, serves via Playground and `/v1` (JSON, SSE, bad key 401; embeddings for the embedding pool), then: device page, usage and metrics, audit rows, **engine overrides** (applied then lifted), **benchmark** (chat only; refused for embeddings), **remote restart**, and revoke (must disappear). Long steps print `[type/kind] 30s …` markers. `E2E_NODE_TYPES` (`web,cli,android` or `none`) limits types. Code in `lib/nodeSuite.ts` and `lib/drivers/`.
   - **web**: second browser context on `web-node.<host>` (Chromium with WebGPU/SwiftShader flags).
   - **cli**: released `splitcortex-node` (`cli-node-latest` or `E2E_CLI_VERSION`) cached by `lib/releases.ts` in `.cache/` (fetched again when the release's published sha256 differs, since the rolling `-latest` asset keeps its name; unpacked once per archive); `join --url --code`, then `run` as a child with a throw-away `SPLITCORTEX_HOME`.
   - **android**: released APK (`mobile-node-latest` or `E2E_MOBILE_VERSION`) on the emulator adb sees; `splitcortex://enroll` deep link, uiautomator taps (`lib/adb.ts`); for `local.splitcortex.com` it runs `adb reverse tcp:443 tcp:443`.
3. **nodes-multi** (`nodes-multi.spec.ts`, `lib/cliNodes.ts`; throw-away pools and keys in the `e2e` org, CLI nodes with a data dir each, one browser tab for the mixed pool). **The CLI nodes run `run --fake`** (the released node's synthetic engine: `tok0 tok1 …`, no model download; `new CliNode()` defaults to it, `new CliNode(false)` / `newCli(false)` runs the real engine). `nodes-multi`'s nodes answer instantly (`QUICK`: 1 ms, no delay between tokens); the shared pair `n1`/`n2` use `STEADY` (20 ms, 200 tokens a second) because the mid-answer tests (a device dying or stopping, a client hanging up) need the answer still streaming; the real engine stays in `nodes-cli` and in the two cases that need it (embedding meaning, the model landing in `--models-dir`). A released CLI node older than the fake engine fails on the unknown flag: two devices in a round-robin pool share the load (per-device counts from `metrics?nodeId=`), weighted balancing under 12 concurrent requests (only 200/429/503, with `Retry-After`), real telemetry on the device page, a killed device dropped and reconnecting by itself (and `restart` of an offline one: 409, translated), a frozen process (`SIGSTOP`) dropped, an answer cut by `SIGKILL`/`SIGTERM` ending cleanly, device setting (`config --context`) vs admin override vs lifted, the device API signed with the node's own key (`lib/cliNodes.ts nodeAuthHeader`: no/garbage/stale/future/wrong-path/wrong-method/other-key/other-id all one 401; `Range` 206/416; another pool's model 404), a code used once, revocation closing the device API, approval (pending node gets 401, rejecting = delete), a token limit (`429` + `Retry-After`), replacing a pool's model under a device, a CLI + web node in one pool; then the integration cases: every balancing type (`least_in_flight`, `random`) reaches both devices, a client hanging up mid-answer frees the device (`inFlight` back to 0), `finish_reason: length`, usage numbers adding up, roles/system/non-ASCII, a streamed answer's shape, a prompt larger than the device's window (`400 context_length_exceeded` with the numbers, also in Romanian), embeddings on a real device (order, size, `dimensions` + renormalising, `base64` equals `float`, `task` changes the vector, meaning, too many dimensions = 400), taking away a pool's model and then the pool under a live device (key 404, device API 401), bulk codes enrolling three devices, admin overrides on a device (`keepScreenOn`, `enableMtp`, backend, context bounds, clearing), the CLI's own commands (`status`, `config --models-dir` with the model landing in that folder, `update --check`, `leave`). `E2E_NODE_TYPES=none` in CI.
4. **api** (`control-plane.spec.ts`, `gateway.spec.ts`, `api-security.spec.ts`; throw-away orgs/pools): token checks, `/me`, org rename/slug rules, pools, enrollment codes (one, bulk, cancel, generic 404), usage and metrics shapes, members and roles (needs user 2), audit (filters, paging, export), org delete, errors in en and ro; gateway keys (secret shown once, validation), expiry/limits, auth errors, `Accept-Language`, `/v1/models` scoping, wrong model/endpoint/body, `503` for a pool without a device, `429` + `Retry-After`, revocation, gateway audit rows (polled, batched). `api-edge` (throw-away org, two tiny uploaded models, no device): an expiring key stops (and the audit row says `expired`), organisation limits are shared by every key (requests and tokens per minute, started early in the minute so the window can't roll), `lastUsedAt`, embeddings validation (128 texts, 32,000 characters, tasks, dimensions, encodings: 400 with a message; the edges are not refused), chat validation (media from a wrong role, unknown image/audio types, bad base64, data URLs, addresses, empty media, video: 400 with the code; 65 pictures: 413; a 6 MB picture reaches the gateway). `api-security`: enrollment code allows 3 guesses then is dead with the same generic 404 as an unknown code (attempts read from the code list), cancelled code, other org can't list or cancel codes; keys scoped to pools can't reach a third pool (404, not 503), organisations are isolated at the gateway (same model name in two orgs, keys of a deleted org stop), a request flood leaves a few audit rows, not one per request; model life cycle (non-Hugging Face links 400, a link to nothing ends `failed` with a reason and `retry` fails again, failed/ready can't be served/retried, replacing and deleting a served model changes `/v1/models`). The per-IP limit on `/enroll/*` (30/min) is only tested with `E2E_RATE_LIMIT=1`, because it would make the node projects' enrollments fail for a minute.
5. **ui** (`ui.spec.ts`, `ui-admin`, `ui-app`, `ui-org`, `web-node.spec.ts`; throw-away org): every sidebar page, pool lifecycle, members, plain-member view, Romanian, Playground (wrong key, real key, attachments, narrow window), models (validation, **tiny file upload** into Garage, serve, delete), API keys, audit page, usage/metrics, settings, signed-out flows, Home/About/downloads, account menu and settings, phone layout, sign out, and a sweep of every page in en and ro for untranslated keys and script errors. `web-node.spec`: the join screen.
6. **approval** (`approval.spec.ts`, in `nodes-web`): an approval pool, a pending web node, admin approves, it comes online.
7. **tenancy**: user 2 can't read or delete user 1's org.
8. **cleanup** (setup's teardown, runs after failures): revokes the run's devices and key. Nodes enroll afresh every run and re-download the model.

9. **perf** (`perf.spec.ts`, `lib/perf.ts`; `--project=perf --workers=1`): performance of **our code, not of a model or the runner**, from a client on the runner against stg. A throw-away pool (`least_in_flight`) with a **fleet of fake CLI nodes** (`new CliNode({firstTokenMs: 20, tokensPerSec: 100})` = `run --fake`; `PERF_NODES`, default 12, enrolled one every 6 s because `/enroll/*` allows 30 calls a minute per address and a device uses two). Measures: one request at a time (platform overhead = measured minus the fake device's own time), streams (time to first token, gap between tokens, per-token overhead), concurrent streams up to one per device, more streams than devices (served or refused with 429/503, quickly, none hung), cheap paths (`/v1/models`, wrong key 401, unknown model 404), a device killed under load (failures, time until the pool serves again, reconnect time of the restarted device), control plane reads and writes (p50/p95, API key create/delete with its audit record), and how long the **metering** takes to show every request. Assertions are only about correctness under load (every answer exact `tok0 tok1 …`, refusal kinds, nothing hung, failover under 15 s); **timings are reported, not asserted** (`perf-results/results.json` and `summary.md`, compared with the previous successful run's artifact: ⚠ = p95 above 2x plus 25 ms; `PERF_ENFORCE=1` turns that into a failure). The client's own event-loop lag is recorded, so a client-bound run can be told from a slow platform. Needs the released CLI node with `--fake`.

**Known gaps**: code expiry after 10 minutes (no way to age a code); gateway instance drain and multi-instance; a model change while a device is mid-download; foreground-only behaviour of the web and Android nodes; multimodal on a real device (no multimodal model in setup) (only the gateway's 400s are asserted); a successful Hugging Face import is exercised only by setup (the failure path is asserted); resume after a gateway restart.

## Running

- Local: `cp .env.example .env`, fill `E2E_EMAILS`/`E2E_PASSWORDS` (users from `chart/values-local.yaml`), `pnpm install`, `pnpm install:browsers`, `pnpm test` (`test:ui` for the Playwright UI; headed locally, headless in CI). `E2E_RATE_LIMIT=1` also runs the per-IP enrollment limit test (it blocks other enrollments from the machine for a minute, so run it alone: `--project=setup --project=api -g "limit calls per IP"`). Start the emulator first or Android is skipped. `.env` holds nothing else secret.
- CI `e2e.yaml`: daily 03:17 UTC and manual (`cli_version`, `mobile_version`), against stg, environment `stg` (secrets `E2E_EMAILS`, `E2E_PASSWORDS`). A `prepare` job runs `--project=setup` once (no creation race), then a parallel matrix: **platform** (`api`, `ui`, `tenancy`), **web**, **cli**, **multi node** (`nodes-multi`, `E2E_NODE_TYPES=none`), **android** (KVM + emulator, API 34 x86_64), each with its own `E2E_NODE_TYPES` and report artifact; then **perf** (`needs: e2e` succeeded; own job, `perf_nodes` input; downloads the last successful run's `perf-results` artifact as the baseline, appends `summary.md` to the job summary, uploads `perf-results`, 30 days). Caches: pnpm, browsers, release downloads, AVD snapshot.
- **Users in stg**: chart value `e2e.users` (`{email, hash}`) is appended to Dex `staticPasswords` by `dex-config.yaml`; empty in git, `deploy.yaml` (stg only) bcrypts the secrets with `htpasswd`. Local users live in git-ignored `values-local.yaml`.

## Verified

`setup`, `api` (including `api-security`) and `nodes-multi` pass against stg (`BASE_URL` in `.env`) with two users and the released CLI node `cli-node-v23.0.1`; the multi-device cases (balancing, a dying or frozen device, mid-answer cuts, the device API, mixed CLI + web) run on real CLI nodes and a Chromium tab. The per-IP enrollment limit test is opt-in and was not run in the normal pass. `ui` and `tenancy` last passed (40 tests together with `setup` and `api`) against the local stack. Selectors are the English strings. The Android engine has never run on an emulator, SwiftShader WebGPU in CI is untested, and release asset names are assumed from `rolling-release.yaml`.

## Gotchas

- **GitHub rate limit**: `lib/releases.ts` looks the node releases up through the GitHub API. Anonymous calls are 60 an hour per address, shared on CI runners, so the jobs pass `GITHUB_TOKEN: ${{ github.token }}` (not exported by default); locally set `GITHUB_TOKEN` too. When the lookup still fails, the newest copy in `.cache/` is used (with a warning). The node's own `update --check` in `nodes-multi` is anonymous and already tolerates the limit.
- `AddModelDialog` and confirm dialogs are `alertdialog`, the others `dialog`. A Fluent toast renders its text twice: use `.first()`. A closed dialog stays in the DOM for its exit animation: wait with `dialogsClosed(page)` (`lib/ui.ts`). Escape doesn't close the add-device dialog; click Close.
- "Start" matches "Restart": use `exact: true`. The pool page has four comboboxes: find the model picker by placeholder.
- `ensurePool` always checks the pool serves its model (a crashed run once left one without), and node specs assert it before enrolling.
- `cliNodeBinary()` unpacks the release once into `.cache/<tag>/unpacked-<archive mtime>` and never again: unpacking over a running node's executable made it fail loading its model with a bare `No such file or directory (os error 2)`. The CLI node projects share that folder.
- The web node starts by itself after joining; the driver presses Start only if it didn't. `actionTimeout` is set so a wrong locator fails in 30 s.
