# Layout: chart and services

Summary in [CLAUDE.md](../CLAUDE.md).

- `chart/`: Helm chart, currently a **skeleton**: `Chart.yaml`, `templates/_helpers.tpl` (naming/label helpers) and empty `values.yaml` (local dev), `values-stg.yaml`, `values-prd.yaml` (overrides layered with `-f`), plus an optional git-ignored `values-local.yaml` for personal local overrides. It depends on the official **Traefik** chart (`traefik/traefik` 42.4.0 from https://traefik.github.io/charts, toggle with `traefik.enabled`, default on) and **cert-manager** (`jetstack/cert-manager` v1.21.3 from https://charts.jetstack.io, toggle with `cert-manager.enabled`, default on, CRDs enabled in `values.yaml`). **Dex** IdP (`dex/dex` 0.26.0 from https://charts.dexidp.io, toggle with `dex.enabled`; `image.tag: latest` with `pullPolicy: Always` (moving tag, not reproducible; pin a version tag if that matters); `enablePasswordDB: true`, `oauth2.skipApprovalScreen: true` (no grant-access screen), `expiry.idTokens: 15m` (Dex access tokens), refresh tokens 2160h (~3 months) for both `validIfNotUsedFor` and `absoluteLifetime`, `reuseInterval: 30s` so two racing renewals (two tabs, a reload) do not fail with "refresh token claimed twice", Kubernetes storage; exposed through Traefik ingress at `https://dex.splitcortex.127.0.0.1.nip.io` (issuer URL; TLS from `root-ca-issuer`, `rate-limit-general` middleware, which assumes namespace `splitcortex`; stg/prd override this to `https://dex.stg.splitcortex.com` / `https://dex.prd.splitcortex.com` with the `letsencrypt` ClusterIssuer; each also registers the public `splitcortex-ui` static client and `allowedOrigins: ["*"]` plus an `allowedHeaders` list); the initial user `alinflorinciu@icloud.com` with a bcrypt hash is only in git-ignored `values-local.yaml`). **PostgreSQL** (`groundhog2k/postgres` 1.6.8 from https://groundhog2k.github.io/helm-charts/, toggle with `postgres.enabled`; service name `postgres`). `templates/postgres-credentials.yaml` generates the random superuser and app-user passwords once (reused on upgrade via `lookup`) into the fixed-name Secret `postgres-credentials` (kept on uninstall, matching the retained PVC), which also carries a ready `DATABASE_URL`; the subchart values only reference that Secret's keys, never passwords. `templates/cluster-issuers.yaml` defines ClusterIssuers as Helm post-install/post-upgrade hooks (CRDs and webhook come from the same release; install with `--wait`; not removed on uninstall): `root-ca-issuer` (CA issuer backed by a self-signed root, via a `selfsigned-issuer` bootstrap) everywhere, and `letsencrypt` (Let's Encrypt **production** ACME, HTTP-01 through Traefik) only in stg/prd, enabled by setting `letsencryptEmail` (the only issuer-related value; in `values-stg.yaml`/`values-prd.yaml` it is the placeholder `"${LETSENCRYPT_EMAIL}"`, substituted at deploy time with `envsubst '$LETSENCRYPT_EMAIL' < chart/values-<env>.yaml` from a CI variable, and the template fails if the placeholder is left in; CI validate substitutes a dummy address; names and settings are hardcoded in the template, do not add issuers to values); `Chart.lock` is committed and `chart/charts/` is git-ignored (run `helm dependency build chart`). Workloads, services, ingress and secrets will be re-added as the services land. Constraints for when they are:
  - Postgres is external; the gateway needs a direct connection (it uses `LISTEN`), not PgBouncer transaction mode.
  - Gateway default is 1 replica (registry is per process; more replicas need sticky routing by pool). The ingress controller is Traefik; SSE and wss must not be cut by Traefik's entryPoint `respondingTimeouts` (static Traefik config).
  - The gateway server private key comes from a Secret mounted as a file; only the public key and wss URL go to the control plane as plain config. Prefer `existingSecret` outside dev; no inline secrets in stg/prd.
  - External ingress / cert-manager are supported. External ingress controller: `traefik.enabled=false`, set `ingress.className` (also used by the ACME HTTP-01 solver) and `dex.ingress.className`, `rateLimit.enabled=false` unless it is Traefik with its CRDs, and replace the `traefik.ingress.kubernetes.io/*` annotations on the Ingresses. External cert-manager: `cert-manager.enabled=false` (CRDs and webhook must already exist; our `root-ca-issuer`/`letsencrypt` names must not clash). To use the external cert-manager's own issuers, also set `clusterIssuers.enabled=false` and point the Ingress `cert-manager.io/cluster-issuer` annotation at them.
  - Dev only, toggle `dev.coredns.enabled` (on in `values.yaml`, off in stg/prd): `templates/coredns-custom.yaml` creates the k3s `coredns-custom` ConfigMap in `kube-system` with `rewrite name exact <host> traefik.<ns>.svc.cluster.local` for each host in `dev.coredns.hosts` (currently `dex.splitcortex.127.0.0.1.nip.io`), so pods resolve the nip.io names to Traefik instead of 127.0.0.1. It replaces any existing `coredns-custom`; add new dev hostnames to the list.
  - HTTP to HTTPS: Traefik's `web` entryPoint redirects everything to `websecure` (`traefik.ports.web.http.redirections.entryPoint` in `values.yaml`; 302 in dev, 301 in stg/prd). This is global, so individual Ingresses need no redirect middleware. cert-manager HTTP-01 still works because Let's Encrypt follows redirects. With an external ingress controller, configure the redirect there.
  - The Traefik IngressClass is named `traefik` (`traefik.ingressClass.name` in `values.yaml`), independent of the release name; Ingresses and the ClusterIssuer's HTTP-01 solver use it.
  - Traefik rate limits: `templates/rate-limits.yaml` defines Middlewares `rate-limit-general` (per client IP, 50/s burst 100; web app, control plane, Dex) and `rate-limit-gateway` (per `Authorization` header, 2000/s burst 4000, a coarse flood ceiling only; the gateway enforces real per-key limits). Values under `rateLimit`. They are **not** on the entryPoint (that would throttle the gateway): attach per route via `router.middlewares` / IngressRoute. Nothing is attached until routes exist.
  - No Redis, no serverless. Enrollment goes through the control plane ingress, never the gateway.

- `src/ui/`: web app, containerised with `Dockerfile.dev` (Tilt: Vite dev server with live_update) and `Dockerfile` for production (multi-stage: pnpm test, then pnpm build, then Caddy on 8080 with SPA fallback, `/healthz`, non-root) and `Caddyfile`; chart templates `ui-deployment/ui-service/ui-ingress.yaml` under the `ui:` values (ingress on by default at the web app host). It is a Vite + React + TypeScript app; `src/` is split into `auth/` (OIDC provider, `PrivateRoute`, current user), `components/layout/` (sidebar (always visible on desktop; overlay drawer with a hamburger toggle on mobile), top bar, user menu with the theme and language submenus), `pages/`, `i18n/`, `theme/`, `lib/`; static assets and `locales/` in `public/`.

- `src/control-plane/`: Fastify API (`src/app.ts` builds the app from injected `db` and token verifier so tests need no infrastructure; `routes/`, `plugins/auth.ts`, `dto/` zod DTOs, `db/` with `schema.ts`, `migrate.ts`, `config-changes.ts`; `drizzle/` generated SQL migrations), `Dockerfile` (prod, runs tests, prod-only deps, non-root), `Dockerfile.dev` (Tilt, `tsx watch` on 8080). Chart templates `control-plane-{deployment,service,ingress,migrate-job}.yaml` under `controlPlane:` values (stg/prd override image and host).

- `src/node/`: the endpoint app (Expo + React Native, see Tech stack). Not containerised or deployed by the chart: it is a device app, built locally. `src/app/` routes (Home, Settings), `src/components/`, `src/theme/`, `src/i18n/`.

- `scripts/`: dev helpers. `start-emulator.sh [avd]` boots an Android emulator (no root in the emulator, any image) with `-dns-server 127.0.0.1` and starts `dnsmasq` with `sudo` on 127.0.0.1:53 (privileged; verified working, the emulator reaches `app.splitcortex.127.0.0.1.nip.io` with the CA installed) (answers `*.splitcortex.127.0.0.1.nip.io` with `10.0.2.2`, the host as seen from the emulator, forwards the rest to 1.1.1.1; must be installed), so the local nip.io names reach Traefik with the right hostname. It does not touch the CA (installed by hand once). Debug builds trust user CAs through `src/node/plugins/withDevUserCa.js` (debug source set only, never release).
