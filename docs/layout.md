# Layout: chart and services

Summary in [CLAUDE.md](../CLAUDE.md).

## Chart (`chart/`)

`Chart.yaml`, `templates/_helpers.tpl`, `values.yaml` (local dev), `values-stg.yaml`, `values-prd.yaml` (layered with `-f`), optional git-ignored `values-local.yaml` (personal overrides). `Chart.lock` committed, `chart/charts/` git-ignored (`helm dependency build chart`). Workloads, services, ingresses and secrets are under per-service values blocks (see Services). **One domain setting**: `global.domain` (local `local.splitcortex.com`, stg/prd set their own) is the base of `dex.`, `web-node.` and `gateway.` (the web app itself is on the base domain); ingress hosts/TLS, `controlPlane.gateway.url`, `dev.coredns.hosts` and Dex's `config` are rendered with `tpl`, so write `"dex.{{ .Values.global.domain }}"` (the web app host is `"{{ .Values.global.domain }}"`) (it must be `global` so Dex's subchart sees it). Dex's config Secret is therefore rendered by `templates/dex-config.yaml` (`dex.configSecret.create: false`); because Dex's chart no longer checksums it, a config change needs a Dex restart.

**Dependencies** (each toggled with `<name>.enabled`):

- **Traefik** `traefik/traefik` 42.4.0 (https://traefik.github.io/charts). IngressClass named `traefik` (`traefik.ingressClass.name`), independent of the release name. The `web` entryPoint redirects everything to `websecure` globally (`traefik.ports.web.http.redirections.entryPoint`; 302 dev, 301 stg/prd), so Ingresses need no redirect middleware (HTTP-01 still works).
- **cert-manager** `jetstack/cert-manager` v1.21.3 (https://charts.jetstack.io), CRDs enabled.
- **Dex** `dex/dex` 0.26.0 (https://charts.dexidp.io): `image.tag: latest` with `pullPolicy: Always` (moving tag; pin if reproducibility matters); `enablePasswordDB: true`, `oauth2.skipApprovalScreen: true`, `expiry.idTokens: 15m`, refresh tokens 2160h (`validIfNotUsedFor` and `absoluteLifetime`), `reuseInterval: 30s` (racing renewals from two tabs/reload don't fail with "claimed twice"), Kubernetes storage. Issuer `https://dex.local.splitcortex.com` locally (TLS `letsencrypt`, `rate-limit-general`, assumes namespace `splitcortex`); stg/prd use `https://dex.stg.splitcortex.com` / `https://dex.splitcortex.com` with `letsencrypt` and enable the Google connector (`${GOOGLE_CLIENT_ID}`/`${GOOGLE_CLIENT_SECRET}` placeholders substituted by `envsubst` at deploy time from GitHub environment secrets, never committed; redirect URIs `https://dex.stg.splitcortex.com/callback` and `https://dex.splitcortex.com/callback`; one Google client may serve both, split before prd has real users). Each env registers the public `splitcortex-ui` static client, `allowedOrigins: ["*"]` and an `allowedHeaders` list. The initial local user (bcrypt hash) is only in git-ignored `values-local.yaml`.
- **PostgreSQL** `groundhog2k/postgres` 1.6.8 (https://groundhog2k.github.io/helm-charts/), service `postgres`. `templates/postgres-credentials.yaml` generates random superuser/app passwords once (reused on upgrade via `lookup`) into Secret `postgres-credentials` (kept on uninstall, matching the retained PVC), which also carries a ready `DATABASE_URL`; subchart values only reference its keys.
- **Garage** (object storage, see [control-plane.md](control-plane.md)).
- **ClusterIssuer** (`templates/cluster-issuers.yaml`, Helm post-install/post-upgrade hook, install with `--wait`, not removed on uninstall): the single `letsencrypt` (Let's Encrypt production, **DNS-01 through Cloudflare**) in every environment; no self-signed or HTTP-01 issuer, no ACME account email. Required value `cloudflareApiToken` (Zone:DNS:Edit on the zone of `global.domain`); the token is rendered into the plain Secret `cloudflare-api-token` in the release namespace (cert-manager's cluster resource namespace; it is also in the Helm release data, so keep the release namespace private). Locally it is in git-ignored `values-local.yaml`; stg/prd carry `"${CLOUDFLARE_TOKEN}"`, substituted by `envsubst` from the GitHub secret `CLOUDFLARE_TOKEN`; the template fails on a missing token or a remaining placeholder; CI validate uses dummies (`--set` for dev). The local domain `*.local.splitcortex.com` resolves to `127.0.0.1` through a wildcard A record plus one for the bare `local.splitcortex.com` (the web app host; a wildcard does not cover it), both DNS only, in Cloudflare, so local certificates are publicly trusted. Let's Encrypt allows 5 identical certificates per week: recreating the local cluster often can hit it. cert-manager runs its DNS-01 self-check against `1.1.1.1`/`8.8.8.8` only (`cert-manager.extraArgs`: `--dns01-recursive-nameservers-only`), because through the cluster DNS the first "no TXT yet" answer gets cached and challenges stay pending for minutes. Name/settings hardcoded; don't add issuers to values.

**Constraints**:

- Postgres is external; the gateway needs a direct connection (uses `LISTEN`), not PgBouncer transaction mode.
- Gateway default 1 replica; more replicas forward internally (see [gateway.md](gateway.md)). SSE and wss must not be cut by Traefik's entryPoint `respondingTimeouts` (static Traefik config).
- Gateway private key comes from a Secret mounted as a file (see gateway.md); only the public key and wss URL go to the control plane. Prefer `existingSecret` outside dev; no inline secrets in stg/prd.
- Dex login theme: `files/dex-theme/{styles.css,theme.js,header.html,logo.svg}` rendered by `templates/dex-theme.yaml` into ConfigMap `dex-theme`, mounted at `/srv/dex/web/themes/splitcortex` (`dex.volumes`/`volumeMounts`) and selected by `dex.config.frontend` (`dir: /srv/dex/web` (required, else Dex uses its embedded assets and ignores the mount), `theme: splitcortex`, `issuer: SplitCortex`, `logoURL: theme/logo.svg`). Overrides only; Dex's own `main.css` loads first. Light/dark: the web app mirrors an explicit choice in the `sc-theme` cookie on the shared parent domain (`ThemeContext.tsx`); `theme.js` (loaded by our `header.html`, Dex's stock one plus a script tag, mounted by `subPath`; re-check it on Dex upgrades) turns it into `data-theme`; no cookie = follow the OS. Language: Dex has no i18n (maintainers closed dexidp/dex#551), so `theme.js` swaps Dex's English strings for Romanian from a small dictionary, driven by the `sc-lang` cookie the web app writes (`lib/sharedCookie.ts`; no cookie = browser language). Unlisted strings (server error messages, scopes) stay English; a Dex upgrade that rewords a string needs the dictionary updated. A public-suffix parent may reject the cookie, then local Dex follows the OS. Not yet checked on a running Dex.
- External ingress controller: `traefik.enabled=false`, set `ingress.className` (also used by the ACME solver) and `dex.ingress.className`, `rateLimit.enabled=false` unless it's Traefik with CRDs, replace `traefik.ingress.kubernetes.io/*` annotations, configure the HTTP→HTTPS redirect there. External cert-manager: `cert-manager.enabled=false` (CRDs and webhook must exist; our issuer names must not clash); to use its issuers set `clusterIssuers.enabled=false` and point the Ingress `cert-manager.io/cluster-issuer` annotation at them.
- Rate limits (`templates/rate-limits.yaml`, values under `rateLimit`): Middlewares `rate-limit-general` (per client IP, 50/s burst 100; web app, control plane, Dex) and `rate-limit-gateway` (per `Authorization` header, 2000/s burst 4000, coarse flood ceiling only; the gateway enforces real per-key limits). `rate-limit-node` (per client IP, 100/s burst 500, `rateLimit.node`) on the node WebSocket: `templates/gateway-node-ingress.yaml` (`gateway.nodeIngress`) puts `/node` on the gateway host(s) in its own Ingress, because nodes send no `Authorization` header and would share one bucket under the gateway limit. **Not on the entryPoint** (would throttle the gateway): attach per route via `router.middlewares`/IngressRoute.
- Dev only, `dev.coredns.enabled` (on in `values.yaml`, off in stg/prd): `templates/coredns-custom.yaml` creates the k3s `coredns-custom` ConfigMap in `kube-system` with `rewrite name exact <host> traefik.<ns>.svc.cluster.local` for each host in `dev.coredns.hosts` (currently the Dex host), so pods resolve the local `*.local.splitcortex.com` names (public DNS says `127.0.0.1`, which inside a pod is the pod itself) to Traefik. It replaces any existing `coredns-custom`; add new dev hostnames to the list.
- No Redis, no serverless. Enrollment goes through the control plane ingress, never the gateway.

## Services

- `src/ui/`: web app, see [ui.md](ui.md). `Dockerfile` + `Dockerfile.dev`, chart `ui-*.yaml` under `ui:` (ingress at the web app host).
- `src/web-node/`: [web-node.md](web-node.md). Containerised like the UI (`Dockerfile.dev` Vite HMR on 8080; production: tests, build, Brotli precompress, Caddy on 8080 with SPA fallback, `/healthz`, non-root; the WASM runtime under `/litertlm/` is revalidated, never cached blindly). Chart `web-node-*.yaml` under `webNode:` (ingress at `web-node.<domain>`, stg/prd override image and host). The control plane's Ingress also lists the web node host (`/api` only; TLS Secret `web-node-tls`, issued through the web node's Ingress).
- `src/control-plane/`: Fastify API (`src/app.ts` builds the app from injected `db` and token verifier so tests need no infrastructure; `routes/`, `plugins/auth.ts`, `dto/`, `db/` with `schema.ts`, `migrate.ts`, `config-changes.ts`; `drizzle/`). `Dockerfile` (prod: runs tests, prod-only deps, non-root), `Dockerfile.dev` (`tsx watch` on 8080). Chart `control-plane-{deployment,service,ingress,migrate-job}.yaml` under `controlPlane:`.
- `src/gateway/`: [gateway.md](gateway.md); chart `gateway-*` under `gateway:`.
- `src/mobile-node/`, `src/cli-node/`: device apps, **not deployed by the chart** (no Dockerfile, chart templates or Tiltfile entry); built by `.github/workflows/<name>*.yaml` (see [commands-and-ci.md](commands-and-ci.md)). The CLI node is a Rust binary installed by `install.sh`/`install.ps1`.
- Android emulator: the local hostnames resolve to `127.0.0.1`, which inside the emulator is the emulator itself, so forward the gateway/web ports with `adb reverse tcp:443 tcp:443`. The certificates are publicly trusted Let's Encrypt ones, so no CA is installed in the emulator and debug builds need no network security config.
