# Desktop node (`src/desktop-node`) details

Summary in [CLAUDE.md](../CLAUDE.md). A **Tauri 2 app for Linux, macOS and Windows that serves inference like a phone node**. It ports the web node's web side ([web-node.md](web-node.md): enrollment, protocol, runtime, compute policy, model manager, UI) and replaces everything that was browser-only with native code. A change to enrollment, protocol, runtime, compute or model code in the web node, the phone app or here usually needs the same change in the others (ported, not shared, like the UI).

## Stack and layout

- **Web side** (`src/`, own pnpm project, same stack and look as `src/ui`/`src/web-node`): Vite, React + React Compiler, TypeScript strict, Fluent UI, react-hook-form + zod (messages are i18n keys), react-i18next en + ro, Vitest, self-hosted Inter, no CDNs, cards. One page, no router. `src/protocol/gen` is generated from `src/gateway/proto` (`pnpm gen:proto`, committed, prettier-ignored).
- **Native side** (`src-tauri/`, Rust, edition 2024): `engine/` (LiteRT-LM), `storage.rs` (model files, device secret), `system.rs` (device info, telemetry, sleep prevention, updater gate), `lib.rs` (plugins, tray, close-to-tray). Capabilities in `capabilities/default.json`; new plugin APIs used from the web side need an entry there.
- **The seam**: `src/native/ipc.ts` is the only file that imports `@tauri-apps/api` (typed `NativeApi`; tests inject a fake). `src/native/http.ts` is `fetch` through Tauri's HTTP client. `src/native/updater.ts` wraps the updater, process and autostart plugins.

## Engine (`src-tauri/src/engine`, `src/engine/native.ts`)

- Google's official **LiteRT-LM C API** (`litert_lm_c_api`, release asset `litert_lm_c_api-1.0.0.zip` of LiteRT-LM v0.19.1: headers and one shared library per platform), **loaded at run time with `libloading`** (`ffi.rs` declares only the ~40 functions used; no bindgen, no link-time dependency). There is no official Rust crate; the community `litert-lm-rs` is Linux/macOS oriented and was not used.
- `scripts/fetch-litert.mjs [triple] [--required]` downloads the zip, **checks the pinned SHA-256**, and copies the target's library into `src-tauri/resources/litert/` (git-ignored; bundled as `litert/` resource; found with `resource_dir()`, `SPLITCORTEX_LITERT_LIB` overrides). Libraries exist for **linux x86_64, linux arm64, windows x86_64, macOS arm64. There is none for macOS x86_64**: the script warns (or fails with `--required`), the app would build but could not serve, so **the release matrix does not build Intel macOS** (see the comment in `desktop-node-release.yaml`). Updating LiteRT-LM = change `VERSION`/`SHA256` in the script and re-check `ffi.rs` against the new headers.
- The library is **never unloaded** (`ManuallyDrop`): it crashed on `dlclose` (found by the test below).
- One model, one generation at a time. `engine_load` (backend `cpu`|`gpu`, context window via `set_max_num_tokens`, MTP via the speculative-decoding config, retried without MTP if the library rejects it, kernel cache in the app cache dir), `engine_generate` (a fresh conversation per request: history through `conversation_config_set_messages`, last turn through `send_message_stream`, sampler top-p/temperature and max output tokens in the session config; text pieces stream to the web side over a Tauri `Channel`), `engine_cancel` (an atomic flag; the stream callback calls `conversation_cancel_process`, the only call the library allows inside a callback), `engine_unload`, `engine_caps`.
- **GPU**: `gpuAvailable` is true on macOS and Windows and on Linux when `libvulkan.so.1` loads. It only gates the automatic CPU-against-GPU measurement; a failed load steps back to the CPU (`ComputeEngine`). The admin override/user setting can force GPU.
- Prompts and completions pass through only to be generated and streamed; nothing is logged or stored (the log plugin is at info level and the engine logs nothing of them).
- **Verified**: `cargo test` loads the real Linux library and resolves every function the app calls (`the_shipped_library_has_every_function`). **Not verified: any generation against a real model on any OS.** Check on a machine with a `.litertlm`: that the conversation stream chunk text is the JSON message the parser expects (`chunk_text` also accepts plain text), the role names the chat templates want (`assistant` is passed as received), GPU backends per OS, the MTP drafter, and that `finishReason` (`length` when the piece count reaches `maxTokens`) is good enough.

## Models, identity, HTTP

- **Models** (`storage.rs`): downloaded by the web side's model manager (signed 8 MiB `Range` requests, resume, SHA-256, replace) and written **in place at an offset** by `model_write` (raw bytes as the IPC body, arguments in headers), in `<app data>/models/`; the hash is streamed in Rust; the engine loads the file by name. File names are validated (`[A-Za-z0-9._-]`, no leading dot).
- **Identity**: the Ed25519 key is a file in `<app data>/secrets/` (mode 0600, directory 0700 on Unix; Windows relies on the user profile's ACL), never the webview's storage; the web-side fallback to `localStorage` exists only outside Tauri (`pnpm dev`, tests). Software key, like the phone's; no OS keychain (a Linux box without a secret service would then have no key). Deleting the app data forgets it; the device must join again and the old node is removed in the web app. The enrollment record and the settings are in the webview's `localStorage` (not secret).
- **No CORS**: the control plane has none and must not get any. Control plane calls (enrollment, `GET /node/me`, model download) use `@tauri-apps/plugin-http` (Rust, normal TLS validation, the capability allows any http/https URL because the user types the address). The gateway WebSocket (wss) is opened by the webview; the gateway does not check `Origin`. A control plane with a self-signed certificate (local Tilt) must be trusted by the OS.
- **Enrollment URL**: typed by the user (the web app's address plus `/api`), `VITE_ENROLLMENT_URL` pre-fills it for development. There is **no deep link yet** (the web app's Add device shows the code; the user types address and code).
- Reported to the control plane/gateway: `platform: "desktop"`, host name, OS, arch, cores, RAM, app version. Telemetry: this app's CPU share and resident memory (sysinfo); battery and temperature are unknown sentinels. The admin `NodeConfig.keepScreenOn` means "keep the computer awake" here.

## Behaviour

- **Tray**: closing the window hides it; the node keeps serving. The tray menu has Show and Quit; a left click shows the window. `--hidden` starts without a window (used by autostart). Sleep prevention (`keepawake`, idle sleep only, the display may turn off) follows the *keep the computer awake* setting; the admin value wins. Not verified: macOS App Nap or a Linux desktop throttling the hidden webview's timers and WebSocket; check with the window hidden for hours.
- **Settings** (web side `localStorage`): compute (auto/CPU/GPU), context window, keep awake, connect and load the model when the app opens; the *App* card has the version, update check/install and *start when I log in* (`tauri-plugin-autostart`, Launch Agent on macOS).
- CSP is set in `tauri.conf.json` (self only, `ipc:`, https/wss connections, inline styles for Fluent/Griffel).

## Packaging, release, auto-update (modelled on cc-agent-flows)

- **Tag `desktop-node-vX.Y.Z`** (own stream, independent of server `vX.Y.Z` and `mobile-node-vX.Y.Z`; tags by hand). `.github/workflows/desktop-node-release.yaml` creates a GitHub release named after the tag (**not** marked latest: that badge is the server's), then builds with `tauri-apps/tauri-action@v1` on a matrix of **linux x86_64 (`ubuntu-22.04`), linux arm64 (`ubuntu-22.04-arm`), macOS arm64 (`macos-latest`), windows x86_64 (`windows-latest`)**. Each job sets the version from the tag everywhere (`scripts/set-version.mjs`: `package.json`, `tauri.conf.json`, `Cargo.toml`; also `VITE_APP_VERSION`), fetches that target's library with `--required`, builds and uploads deb/rpm/AppImage, dmg/app.tar.gz, NSIS exe/msi plus the signed updater bundles (`createUpdaterArtifacts`). **No release-cache workflow** (decided): release builds start with a cold Rust cache on a tag (`rust-cache` still keys on the target).
- **Auto-update**: `tauri-plugin-updater` with the endpoint `https://github.com/alinflorin/splitcortex/releases/download/desktop-node-updater/latest.json`. cc-agent-flows uses `releases/latest/download`, which cannot work here (the repository's latest release is the server's), so a **rolling release `desktop-node-updater`** (pre-release, created on the first run, never delete) holds only `latest.json`, rebuilt after every desktop release from that release's assets by `scripts/make-latest-json.py` (the parallel matrix jobs would race on a shared file). On Linux only an **AppImage** can update itself (`can_self_update`). The app checks once when it opens and has a *Check for updates* button; install downloads, verifies the signature, installs and relaunches.
- **Signing**: the update bundles are signed with a minisign key. The **public key is in `tauri.conf.json`**; the private key must be in the repository secrets **`DESKTOP_NODE_SIGNING_PRIVATE_KEY`** and `DESKTOP_NODE_SIGNING_PRIVATE_KEY_PASSWORD` (GitHub does not accept empty secrets, so the key has a password). The key was generated on the maintainer's machine at `~/.config/splitcortex/desktop-node-updater.key`, its password next to it in `desktop-node-updater.password`. **Back it up; losing it means installed apps can never update; never commit it.** Replace it with `pnpm tauri signer generate` (then update the pubkey in `tauri.conf.json`; installed apps still trust the old one, so rotate before the first public release).
- **OS code signing is not set up**: macOS builds are not signed/notarized (Gatekeeper will warn, the user opens it via right-click or `xattr -cr`), Windows builds are not Authenticode-signed (SmartScreen warns). Add `APPLE_*` / `WINDOWS_CERTIFICATE` secrets to `tauri-action` when wanted.
- **CI** (`desktop-node.yaml`, PR/push with path filter): on linux x64/arm64, macOS and Windows: typecheck, prettier check, Vitest, build, fetch the library, `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`. No images, no deploy, no chart.

## Commands (in `src/desktop-node`)

`pnpm install`, `pnpm dev` (Vite on 5175, web side only, no native commands), `pnpm litert:fetch` (host library), `pnpm tauri dev` (full app; its before-command fetches the library and starts Vite), `pnpm tauri build`, `pnpm typecheck`, `pnpm test`, `pnpm format`/`format:check`, `pnpm gen:proto`; Rust: `cargo fmt|clippy|test` in `src-tauri`. Linux build needs `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf`.

## Not built / open

macOS Intel; deep link for enrollment; battery and temperature telemetry; hardware-backed or keychain identity; OS code signing; running any of it against a real model (see Engine).
