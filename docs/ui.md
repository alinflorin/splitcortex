# Web app (`src/ui`)

Rules: [CLAUDE.md](../CLAUDE.md).

## Stack and conventions

- Vite, React (compiler via the experimental Rust port: `react({ compiler: true })` + `oxc-transform-react`), strict TS (no `any`), Fluent UI only, react-hook-form (`mode: 'onTouched'`) + zod (messages are i18n keys), React Router, TanStack Query.
- **i18n**: react-i18next; language order: URL prefix (`/ro/...`), then localStorage (`sc-lang`), then browser, fallback en; en + ro; **both languages are indexed, each at its own URL** (see SEO); JSON in `public/locales/<lng>/translation.json`. **Theme**: Fluent teams light/dark, System/Light/Dark, persisted; theme and language pickers live in the avatar menu (also signed out).
- **No CDNs**: Inter self-hosted (`@fontsource-variable/inter`, `src/fonts.css`). The one decided exception is Google Analytics (see **Analytics**).
- **Tests**: Vitest (jsdom, `src/test/setup.ts` stubs `matchMedia`/`ResizeObserver`), RTL, next to the code; use `renderApp` from `src/test/render.tsx`; mock `react-oidc-context` with `vi.mock`; the chart package is mocked (no canvas).
- **Design**: light, airy, hairline borders, no heavy shadows, no gradients in the UI chrome. **Brand colours come only from the logo** (success states are mint, in-progress states violet; violet `#6C7BF2`→`#4A5BE6`, mint `#2CE6C5`→cyan `#14B8D4`) through `src/theme/brand.ts` (`BRAND` + Fluent brand tokens generated from `#4A5BE6` and laid over the Teams themes); never write brand hex values elsewhere. `web-node`, `mobile-node` and the Dex theme (`chart/files/dex-theme/styles.css`) hold hand copies, kept in sync. Every page uses `components/layout/PageHeader`. **One layout** (`components/layout/AppShell`): a top bar on every page (logo = Home, then Home, Organisations, Playground, About, Contact, avatar menu), a **breadcrumb** on organisation pages (`Breadcrumbs`: Organisations › org › section, or › Pools › pool › node; it replaces any "back" link), and the page. The **sidebar exists only inside an organisation** (`/organisations/:orgId/*`): org name + role, then its pages; 232 px, flat (only hover and the selected page are filled), collapses to a 56 px icon rail (labels move to tooltips; remembered in `localStorage` key `sc-sidebar-collapsed`). Below 1024 px the top links and the sidebar become one overlay drawer from the hamburger (organisation pages first, then the top-level links). App pages fill one 1280 px content column (Home is the exception: full width, it lays out its own 1280 px column so the scroll tour spans the screen); forms keep a 640 px column. Below 600 px (or on coarse pointers) buttons and nav items are at least 44 px tall (`index.css`). Empty lists use `components/cards/EmptyState` (icon, sentence, primary action). Short route fade-in (`.sc-enter`, off under `prefers-reduced-motion`).

## Auth

**Dex OIDC** via `react-oidc-context` (public client `splitcortex-ui`, code + PKCE). Dex URL from `window.location` (`<domain>` → `https://dex.<domain>`; `VITE_OIDC_AUTHORITY` overrides). No end-session endpoint: sign-out clears the local session. Dex CORS is wide open (`web.allowedOrigins: ["*"]`, plus `web.allowedHeaders` for preflight). Tokens last 15 min and `automaticSilentRenew` only runs while a page is awake, so `PrivateRoute` tries `signinSilent()` before sending an expired session to Dex, `SignInOnRenewFailure` signs in again after a failed renewal, and every call gets its token from `auth/useFreshToken.ts` (renews under 30 s, one shared renewal; `useRequest` replays once after a 401). Home, About, Terms, Privacy and Contact are public (each in en and ro, see **SEO**), everything else is behind `PrivateRoute`.

## Data and feedback

- Control plane calls through TanStack Query (`src/api/`: `client.ts` fetch + zod parsing, same-origin `/api` or `VITE_API_URL`; `hooks.ts`; `ApiProvider` shows failed mutations as toasts; `schemas.ts` hand-synced DTOs). Queries wait for the OIDC token. Role gating (`lib/roles.ts`) mirrors the server and is only a convenience.
- Use `useConfirm()` and `useToast()` (`components/feedback/`), not ad-hoc dialogs.

## Layout and pages

- **Cards, never tables.** `components/cards` (`CardList`, `ItemCard`, `Stat`/`StatRow`): one column on mobile, `variant="grid"` from 720 px.
- **Navigation.** Top bar and breadcrumb as above; inside an organisation the sidebar shows only that organisation (`OrgNav.tsx`): org name + role label, then Models/Pools/API keys/Members/Usage/Metrics/Audit log/Settings (API keys, Audit, Settings admin-only). Routes (all private): `/organisations`, `/organisations/:orgId/{pools, pools/:poolId, models, api-keys, members, usage, metrics, audit, settings}`, `.../nodes/:nodeId`, `/playground`, `/user-settings`.
- **Pools list**: green/amber dot and "online / total", refreshed every 10 s.
- **Pool screen**: devices, with admin buttons **Add web node** (creates a code, opens `https://web-node.<domain>/#code=...`; `VITE_WEB_NODE_URL` overrides), **Add many devices** (`BulkEnrollDialog`, 1..50 codes, CSV, cancels unused on close), **Add device** (`EnrollDeviceDialog`: code + QR with countdown, API address, closes itself when a node appears); served models; pool usage; **Benchmarks** (`PoolBenchmarks`, polls every 3 s while running).
- **Node page**: status, CPU, memory, battery/temperature, device info, approve/revoke, admin **Restart** (confirm; disabled unless online), engine card with admin overrides (compute, context 512–131072, MTP, keep-screen-on; saved on change/blur); polls every 10 s; shows `live.modalities`.
- **API keys**: cards with status/scope (**Expiring soon** under 7 days); create dialog (org or pool checkboxes, expiry, limits); **Change expiry** (also revives); one-time secret dialog with **Use this key** (curl/Python examples; gateway URL `gateway.<domain>/v1`, `VITE_GATEWAY_URL` overrides, `lib/gateway.ts`); **Edit limits**; revoke.
- **Models**: status, progress, retry, delete; add from a Hugging Face link or upload with part-level retry (`lib/uploadParts.ts`); **Type** Chat/Embeddings (embedding models are left out of the Playground picker).
- **Account settings**: name/email and a danger zone deleting the account (`DELETE /api/me`; the toast names orgs where the user is sole owner).
- **Audit log** (admin/owner; plain members are redirected): newest first, action label `audit.actions.<action>` (new actions need en + ro labels), filters by category and outcome, **Load more** (`useInfiniteQuery`), CSV/JSON export (`lib/saveFile.ts`).
- **Limits**: `LimitsFields` (requests/min, tokens/min, tokens/day; empty = unlimited) in org settings, key creation, per-key dialog.
- **Playground**: chat with a pool. The user **pastes an API key** (component state only); `GET /v1/models` fills the picker; `POST /v1/chat/completions` streams SSE (`lib/chatStream.ts`; stop aborts so the gateway cancels the node). Options: system prompt, temperature, max tokens; shows time to first token and tokens/s. **Attachments** (`lib/attachments.ts`, paperclip/drop/paste, plus a microphone via `MediaRecorder`): images the gateway takes (JPEG/PNG/GIF/BMP ≤ 1 MiB) go as is, others are scaled to 1024 px JPEG; audio (wav/mp3/flac ≤ 5 MiB) as is, other formats decoded with Web Audio to 16 kHz mono WAV (≤ 10 min); text files (≤ 200 KiB) pasted as a fenced `[File: name]` block; PDFs/binaries refused. Sent as OpenAI parts; a text-only message stays a string. A warning shows when the model's `input_modalities` lacks an attached kind. **No chat memory**: the conversation is resent each turn, refresh clears it, and the page respects `max_media_bytes`. Markdown via `react-markdown` (no raw HTML). Calls go to **`/v1` on the app's own origin** (`getPlaygroundBaseUrl`), routed to the gateway by `gateway.appIngress`, so **no CORS on the gateway**.
- **Home** (`pages/Home.tsx`): landing with an animated `NetworkDiagram`, a **scroll tour** (`components/marketing/ScrollTour.tsx` + `tourScene.ts`: a Three.js flight in the logo colours, as a story in 4 chapters from `home.tour`: old devices on a desk (a phone, a Pi with GPIO header and ports, a laptop whose lid opens), enrolment (key/shield glyphs float up, screens wake with a heartbeat, and long cables leave each device down the aisle to the hub (a sphere split like the logo: violet half, mint half, bright seam, wireframe net) with pulses flowing outward: the devices feed the fleet, they take nothing from it), one pool in an aisle of racks of procedural phones, Pis and laptops, then a side view following one request app → gateway → device and the tokens streaming back (the first device drops out and another takes over); a 480vh block with a sticky stage; lazy-loaded, follows the app theme via `TourScene.setTheme` (bloom in dark only), static frame under `prefers-reduced-motion`, hidden without WebGL), steps, feature cards, a curl example, **Run a node** (`AppDownloads bare`), **Endpoints** (gateway base URL and `<origin>/api`, with copy buttons) and a call to action; signed-out visitors get "Get started" (Dex sign-in). **About**: the story and the two-leg flow, plus links to the public `/terms`, `/privacy` (`pages/Legal.tsx`, copy in `legal.*`) and `/contact` (`pages/Contact.tsx`, placeholder details in `contact.*`). Public copy keeps internal plans, pricing and the tech stack out (WebGPU and LiteRT-LM are named on purpose). Shared pieces in `components/marketing/`; copy in `home.*`/`about.*`.
- **`AppDownloads`** ("Run a node", `#run`): **Mobile app** (APK → `releases/tag/mobile-node-latest`; store buttons inert), **Command line** (`curl … install.sh | sh`, `irm … install.ps1 | iex`, release `cli-node-latest`; scripts from GitHub raw `src/cli-node/install.*`), **Web node** (open without a code; share via `navigator.share`, else copy). Each stream has a rolling `<stream>-latest` release rewritten by `rolling-release.yaml`.
- **Version**: the account menu (and the organisation sidebar footer) shows the Helm chart version from `/version.json` (Caddy serves env `APP_VERSION` = `.Chart.Version`; Vite dev has the same route).

## Charts

`@fluentui/react-charts` only, wrapped by `components/charts/TimeCharts.tsx` (`ChartCard`, line or stacked bars). `MetricsView` shows **live** charts (15 s refresh, a switch freezes, ranges 15 min–7 days) at org (**Metrics** page), pool (pool screen) and node (node screen, telemetry only) level; device charts include **measured tokens/s** and **failure rate** beside the reported tokens/s. `UsageView` has request and token charts above its period cards.

## SEO

Goal: the five public pages (Home, About, Terms, Privacy, Contact) are found in en **and** ro; the signed-in app and every host that is not the public site never are. The same image runs on local, stg and prd, so nothing environment-specific is baked into the build.

- **URLs**: English at the bare path (`/about`), Romanian under a prefix (`/ro`, `/ro/about`). `seo/pages.ts` (`PUBLIC_PAGES`, `localizedPath`, `parsePublicPath`) is the one list; the sitemap, hreflang, canonical URLs, the prerender and the footer all come from it. `App.tsx` mounts the public routes once per language. Links to a public page go through `useLocalePath()` (`/about` -> `/ro/about` for a Romanian reader); new links to Home/About/Terms/Privacy/Contact must too.
- **Language and URL stay in step** (`seo/LocaleSync.tsx`, in `AppShell`): switching language (menu or the footer's language links) goes to the same page in the other language; a bare public URL opened by someone whose saved or browser language is Romanian goes to `/ro/...` (replace, no history entry); back/forward and links to the other language's URL change the language. Sign-in returns (`/?code=...&state=...`) are left alone; `returnToOf` sends a user with no target to the home page of their language. Crawlers send no saved language and an English browser, so they see each URL as written. The signed-in app has no language in its URL.
- **Head** (`seo/head.ts`, `seo/Seo.tsx`): one pure `buildHead` makes title, description, robots, canonical, hreflang (`en`, `ro`, `x-default` = English), Open Graph (+ `og:locale` and alternates), Twitter card and JSON-LD (Organization + WebSite on Home, BreadcrumbList elsewhere). It is used by the prerender and, through `applyHead`, by the running app on every navigation (tags carry `data-seo`). Texts are `seo.*` in both locale files (title up to 65 characters, description up to 170; a unit test checks every page and language). Any other path (the signed-in app, unknown URLs) gets `noindex, nofollow` only.
- **Prerender** (`pnpm build` = `tsc -b && vite build && vite build --ssr src/entry-server.tsx --outDir dist-ssr && node scripts/prerender.mjs`): `entry-server.tsx` renders the real app (Fluent `RendererProvider`/`SSRProvider`, a stub signed-out `AuthContext`, `StaticRouter`, a per-language i18n instance from the JSON files) with `renderToString`; `scripts/prerender.mjs` writes `dist/<path>/index.html` for every public URL (HTML in `#root[data-prerendered]`, Griffel styles and the head in `<head>`), `dist/app.html` (the content-less shell for everything else, `noindex`) and `dist/sitemap.xml`. **No hydration**: `main.tsx` waits for `i18nReady`, then `createRoot` replaces the HTML in one go, so crawlers, link previews and first paint get the real page, and users see no blank screen. Pages must therefore render without a browser: no `window`/`document` at render time except what `prerender.mjs` stubs (`location`, `localStorage`, `matchMedia`), `useSyncExternalStore` needs a server snapshot, effects are fine. The build fails if a page renders no `<h1>`. An inline script in `index.html` hides the (light) prerendered page and paints the dark background for dark-theme users until the app takes over.
- **Host at runtime**: the prerender cannot know the domain, so canonical/hreflang/Open Graph URLs, the sitemap and the endpoints shown on Home carry `{{.Host}}`, which Caddy's `templates` directive fills in per request (any other `{{` is escaped). Hence no `.br` copies of `.html`/`.xml` (`templates` needs the plain text; `encode` still gzips/zstds them).
- **Caddy** (`Caddyfile`): `/robots.txt` and `/sitemap.xml` by environment; `@app` routes (`/organisations*`, `/playground`, `/user-settings`) serve `app.html` with `X-Robots-Tag: noindex`; everything else is a file (`file_server { disable_canonical_uris }`, so `/about` and `/about/` are served in place, no redirect hop); anything that is not a file is a real **404** with the shell (the app shows its not-found page), not the index page with 200; hashed `/assets/*` are immutable, everything else `no-cache`.
- **Indexable only in production**: `SEO_INDEXABLE=true` (chart `ui.seo.indexable`, set in `values-prd.yaml`). Everywhere else (local, stg) every response has `X-Robots-Tag: noindex, nofollow, noarchive`, `/robots.txt` is `Disallow: /` and `/sitemap.xml` is 404. In production `robots.txt` allows everything except `/api/` and `/v1/` and announces the sitemap; the signed-in pages are deliberately **not** disallowed (a crawler must be able to read their `noindex`). The other hosts (dex, web-node, gateway, `/api`, `/v1`) get `X-Robots-Tag` from the Traefik `noindex` middleware (`chart/templates/noindex.yaml`, attached next to the rate limit); the web node's Caddy also serves `Disallow: /`.
- **Footer** (`components/layout/SiteFooter.tsx`, public pages only): links to every public page (the legal pages are reachable from anywhere, which Google's OAuth consent-screen review also wants from the home page) and plain `hreflang` links to the page in the other language.
- **Assets** in `public/`: `og-image.png` (1200x630, source `scripts/brand/og-image.html`, rendered with Chromium at 1200x630), `logo-192.png`, `logo-512.png`, `apple-touch-icon.png`, `favicon.ico` (from `logo.svg` with `rsvg-convert` and `magick`), `site.webmanifest`. Regenerate them if the logo changes. Brand hex values in these files and in `index.html` (`theme-color`) are hand copies of `theme/brand.ts`.
- **Adding a public page**: add it to `PUBLIC_PAGES`, a route in `publicRoutes()` (`App.tsx`), `seo.<key>.title|description` in en and ro, and a footer label (`SiteFooter`); the prerender, sitemap, hreflang and the e2e list (`e2e/tests/seo.spec.ts`) follow.
- **Tests**: `seo/*.test.ts(x)` (paths, head, LocaleSync) in Vitest; `seo.spec.ts` in e2e (prerendered HTML without JS, robots/sitemap per environment, noindex headers on every host, 404s, no redirect hops, language/URL sync in a browser).
- **Not done / needs a human**: Search Console and Bing Webmaster verification of the production domain and submitting `/sitemap.xml`; the Contact page still holds placeholder details (it is indexable; replace them before the site is announced).

## Analytics

Google Analytics 4 (`gtag.js` from `googletagmanager.com`, **the only third party the browser talks to**; a decided exception to "no CDNs"). One stream per app: the web app `G-KYDDYPE4NM`, the web node `G-DY77W04DVM` (public ids, set in `chart/values-prd.yaml`).

- **Production only**: the id comes from the chart (`ui.analytics.measurementId`, `webNode.analytics.measurementId`, empty everywhere else) through the env var `GA_MEASUREMENT_ID`, which Caddy serves at `/config.json` (`{"analyticsId": ""}` outside production). The app fetches it at start; no id (local, stg, the Vite dev server) = no banner, no script, no request to Google. Same image everywhere, so nothing is built in.
- **Consent first** (`analytics/consent.ts`, `ConsentBanner.tsx`): a banner (en + ro, `consent.*`) with Accept and Decline looking alike and a link to the privacy policy; the choice is in `localStorage` `sc-consent`. "Cookie settings" in the account menu (shown only where an id is set) asks again. Before Accept nothing is loaded: `gtag.js` is injected only on `granted`. Consent Mode v2 defaults are all `denied` (analytics and advertising storage), `allow_google_signals` and ad personalization are off. Declining or withdrawing sets `ga-disable-<id>`, revokes consent and deletes the `_ga*` cookies.
- **What is sent** (`analytics/gtag.ts`): page views only, from `Analytics.tsx` (every route change in the web app; once in the web node). The path has organisation, pool and device ids (and any uuid or long hex segment) replaced by `:id`; no query and no hash (sign-in returns carry `code`/`state`, the web node's join link carries the code in the fragment); the title is the generic one. Never anything typed, prompts, answers, keys or codes. The privacy policy (`legal.privacy`: "Analytics and cookies", Sharing, Your rights) and the terms (`legal.terms`: "Cookies and analytics") say so, in en and ro: consent-based, Google as processor, no advertising use (ad storage, Google signals and personalisation off), possible processing outside the EEA, limited retention, withdrawal under Cookie settings. Keep them in step with this section.
- The web node has its own copy of `analytics/` (no shared code between the projects; keep them in step); its banner links to the web app's privacy policy (`web-node.<domain>` -> `<domain>/privacy`).
- **Tests**: Vitest (`analytics/*.test.ts(x)`: path cleaning, nothing loaded before consent, withdrawal, banner flow) in both projects; e2e `analytics.spec.ts` (requests to Google are blocked there).
- **Needs a human**: in GA4, set the data retention you want (Admin > Data collection), turn off Google signals and ad personalization, and keep the stream's enhanced measurement off if you want strictly page views (it also sends scroll and outbound clicks).
