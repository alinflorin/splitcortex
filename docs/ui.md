# Web app (`src/ui`) details

Summary in [CLAUDE.md](../CLAUDE.md).

- Lives in `src/ui` (pnpm). Also: React Router (`BrowserRouter`), react-i18next (language detected from localStorage then the browser, fallback en; supported en + ro; translations are static JSON in `public/locales/<lng>/translation.json`, loaded over HTTP), Fluent `teamsLightTheme`/`teamsDarkTheme` (preference System/Light/Dark, default System = follow the OS, persisted; theme and language pickers are submenus of the avatar menu in the top bar, also available when signed out), Tests: **Vitest** (config in `vite.config.ts`, jsdom, globals, setup in `src/test/setup.ts`) with React Testing Library and jest-dom; tests live next to the code as `*.test.ts(x)`, and use `renderApp` from `src/test/render.tsx` (English i18next from `public/locales/en`, Fluent, memory router); mock `react-oidc-context` with `vi.mock`; jsdom gaps (`matchMedia`, `ResizeObserver`) are stubbed in `src/test/setup.ts`. React Compiler via the **experimental Rust port** (`react({ compiler: true })` + `oxc-transform-react`).
- Forms validate with react-hook-form `mode: 'onTouched'` (messages show after a field is touched and blurred). Zod messages are i18n keys, translated at render.
- Web app auth: **Dex OIDC** via `react-oidc-context` (public client `splitcortex-ui`, code + PKCE, user in localStorage). The Dex URL is computed from `window.location` (`app.<domain>` becomes `https://dex.<domain>`; `VITE_OIDC_AUTHORITY` overrides). Dex has no end-session endpoint, so sign-out only clears the local session. A failed silent renewal removes the user and redirects to sign in (`SignInOnRenewFailure` in `OidcProvider.tsx`), because the expired access token (15 min) would otherwise make every API call answer 401 "Invalid token". The client is registered in the chart's Dex config per environment; Dex CORS is wide open (`web.allowedOrigins: ["*"]`; Dex cannot disable CORS and has no header wildcard, so `web.allowedHeaders` lists the headers browsers may send in a preflight, otherwise `OPTIONS /token` returns 403). `PrivateRoute` (layout route) forces login; Home and About are public, Settings is private.
- Fonts: **no CDNs, ever** (fonts, scripts, icons). The UI self-hosts Inter (variable, `@fontsource-variable/inter`, latin + latin-ext subsets for en/ro, declared in `src/ui/src/fonts.css`) and sets it as `fontFamilyBase` on both Fluent themes, so typography is identical on every OS; the files are bundled into `/assets` by Vite.
- Feedback: `src/ui/src/components/feedback/`. `FeedbackProvider` (in `main.tsx`, inside the Fluent provider) mounts the toaster and the confirm dialog. Use `useConfirm()` (`await confirm({ title, message?, destructive? })` resolves a boolean) and `useToast()` (`success/error/warning/info(title, { body?, timeout? })`, `dismissAll`) instead of ad-hoc dialogs and message bars for transient feedback; button labels come from `common.*` i18n keys.
- Data and pages: **TanStack Query** for control plane calls (`src/api/`: `client.ts` fetch + zod response parsing with the Dex `access_token` as bearer, same-origin `/api` or `VITE_API_URL` for a standalone `pnpm dev`; `hooks.ts` per-resource hooks; `ApiProvider` shows failed mutations as an error toast; `schemas.ts` hand-synced copies of the control plane DTOs). Pages: `/organisations` (list/create), `/organisations/:orgId/{pools,pools/:poolId,api-keys,members,usage,settings}` (`pages/organisations/`), private routes. **Navigation lives in the sidebar, not in-screen tabs**: inside an organisation the sidebar shows **only** that organisation (`components/layout/OrgNav.tsx`): a Back item (to the organisations list), a small context label with the organisation name and role (not a heading, so the page's own title is the only heading; org pages have no org title at the top), and Models/Pools/API keys/Members/Usage/Settings (API keys and Settings for admins); the top-level items (Home, Organisations, About, Settings) return outside it. Queries are disabled until the OIDC token exists (the sidebar mounts before sign-in completes). Org pages also include API keys (`api-keys`, admins only: cards with status/scope, create dialog with whole-organisation or pool checkboxes and an expiry, one-time secret dialog with copy, revoke) and Models (`/organisations/:orgId/models`: status, download progress, retry, delete, add from a Hugging Face link or upload with part-level progress/retry in `lib/uploadParts.ts`), the pool screen (settings, nodes, served models, usage) and a node view (`/organisations/:orgId/nodes/:nodeId`: status, CPU, memory, load, battery/temperature, device info, approve/revoke, and an engine card: what the device runs on plus an admin Select for compute backend (device decides/CPU/GPU) a numeric field for maximum context (512 to 131072, empty clears), and device-decides/on/off selects for multi-token prediction and keep-the-screen-on, saved on change/blur; polls every 10 s). **Rate limits** are three free-text numeric fields (requests/min, tokens/min, tokens/day; empty = unlimited, inline error outside 1..max) in `LimitsFields`: an organisation card on the organisation settings page, the key-creation dialog, and a per-key **Edit limits** dialog (the key card shows its limits). **Benchmarks** are a section of the pool screen (`PoolBenchmarks`): a **Run benchmark** button for admins and cards per run with each device's tokens/s, first-token and total time (and the pool total), polling every 3 s while one runs. **Layout convention: cards, never tables or data grids.** Lists use `components/cards` (`CardList` + `ItemCard`, `Stat`/`StatRow`): one column on mobile, `variant="grid"` flows into columns from 720px; filters and toolbars stack on narrow screens, tabs scroll sideways. A pool has its own screen (`/organisations/:orgId/pools/:poolId`: details, devices with an admin-only **Add device** dialog (`EnrollDeviceDialog`: creates a code, shows it as text and as a QR with a countdown, cancels it on close, closes itself when a new node appears), pool-scoped usage). Role gating in the UI (`lib/roles.ts`) mirrors the server and is only a convenience; the server enforces it.
- UI design: light, airy, modern (hairline borders, generous spacing, no heavy shadows). `public/logo.svg` (square icon) is supplied by the owner. The logo and brand name live in the sidebar header on desktop and in the **top bar** (links home) on mobile, where the sidebar is an overlay. `components/AppDownloads.tsx` shows self-hosted badges (`public/badges/*.svg`: APK on GitHub Releases, Google Play, App Store) on Home and above the devices of a pool; the APK badge links to the repo's GitHub Releases; the store URLs are still empty in the `LINKS` constant (badges render unlinked until filled).

## Original frontend rules (verbatim)

- Forms use react-hook-form with zod schemas (via `@hookform/resolvers/zod`). Share zod schemas for API payloads where possible.
- Use Fluent UI components for all UI; do not introduce another component library.
- TypeScript strict mode; no `any`.
