# Web app (`src/ui`)

Summary in [CLAUDE.md](../CLAUDE.md).

## Stack and conventions

- Vite, React (React Compiler via the **experimental Rust port**: `react({ compiler: true })` + `oxc-transform-react`), strict TS (no `any`), Fluent UI only, react-hook-form (`mode: 'onTouched'`) + zod (messages are i18n keys, translated at render), React Router (`BrowserRouter`), TanStack Query.
- **i18n**: react-i18next, language from localStorage then browser, fallback en; en + ro; static JSON in `public/locales/<lng>/translation.json` loaded over HTTP.
- **Theme**: Fluent `teamsLightTheme`/`teamsDarkTheme`, preference System/Light/Dark (default System), persisted; theme and language pickers are submenus of the avatar menu in the top bar (also when signed out).
- **Fonts: no CDNs, ever** (fonts, scripts, icons). Self-hosted Inter (`@fontsource-variable/inter`, latin + latin-ext, declared in `src/fonts.css`) set as `fontFamilyBase` on both themes, bundled into `/assets`.
- **Tests**: Vitest (config in `vite.config.ts`, jsdom, globals, `src/test/setup.ts` stubs `matchMedia`/`ResizeObserver`), RTL + jest-dom, next to code as `*.test.ts(x)`; use `renderApp` from `src/test/render.tsx` (English i18n, Fluent, memory router); mock `react-oidc-context` with `vi.mock`.
- **Design**: light, airy (hairline borders, generous spacing, no heavy shadows). `public/logo.svg` (square icon) supplied by the owner; logo + brand in the sidebar header on desktop and the top bar (links home) on mobile, where the sidebar is an overlay.

## Auth

**Dex OIDC** via `react-oidc-context` (public client `splitcortex-ui`, code + PKCE, user in localStorage). Dex URL computed from `window.location` (`app.<domain>` → `https://dex.<domain>`; `VITE_OIDC_AUTHORITY` overrides). Dex has no end-session endpoint, so sign-out only clears the local session. A failed silent renewal removes the user and redirects to sign in (`SignInOnRenewFailure` in `OidcProvider.tsx`), because the expired 15-min access token would otherwise make every API call answer 401 "Invalid token". The client is registered in the chart's Dex config per environment; Dex CORS is wide open (`web.allowedOrigins: ["*"]`; Dex can't disable CORS and has no header wildcard, so `web.allowedHeaders` lists preflight headers, otherwise `OPTIONS /token` returns 403). `automaticSilentRenew` only runs while a page is awake, so tokens are also renewed on demand: `PrivateRoute` tries `signinSilent()` with the stored refresh token before sending an expired session to Dex, and every API call and upload part gets its token from `useFreshToken` (`auth/useFreshToken.ts`: renews when under 30 s remain, one shared renewal for concurrent calls; `useRequest` replays once after a 401). `PrivateRoute` (layout route) forces login; Home and About are public.

## Feedback and data

- `components/feedback/`: `FeedbackProvider` (in `main.tsx`, inside the Fluent provider) mounts the toaster and confirm dialog. Use `useConfirm()` (`await confirm({title, message?, destructive?})` → boolean) and `useToast()` (`success/error/warning/info(title, {body?, timeout?})`, `dismissAll`), not ad-hoc dialogs/message bars; button labels from `common.*` keys.
- **TanStack Query** for control plane calls (`src/api/`: `client.ts` fetch + zod response parsing with the Dex `access_token` bearer, same-origin `/api` or `VITE_API_URL` for standalone `pnpm dev`; `hooks.ts` per-resource hooks; `ApiProvider` shows failed mutations as error toasts; `schemas.ts` hand-synced DTO copies). Queries are disabled until the OIDC token exists (the sidebar mounts before sign-in completes). Role gating (`lib/roles.ts`) mirrors the server and is only a convenience.

## Layout and pages

- **Cards, never tables or data grids.** Lists use `components/cards` (`CardList` + `ItemCard`, `Stat`/`StatRow`): one column on mobile, `variant="grid"` flows into columns from 720px; filters/toolbars stack on narrow screens, tabs scroll sideways.
- **Navigation lives in the sidebar, not in-screen tabs.** Inside an organisation the sidebar shows **only** that org (`components/layout/OrgNav.tsx`): Back item (to the org list), a small context label with org name and role (not a heading; the page's own title is the only heading), then Models/Pools/API keys/Members/Usage/Metrics/Settings (API keys and Settings for admins). Top-level items (Home, Organisations, Playground, About) return outside it. `src/` is split into `auth/`, `components/layout/` (sidebar always visible on desktop, overlay drawer with hamburger on mobile; top bar; user menu), `pages/`, `i18n/`, `theme/`, `lib/`.
- **Routes** (all private): `/organisations` (list/create); `/organisations/:orgId/{pools, pools/:poolId, models, api-keys, members, usage, metrics, settings}` (`pages/organisations/`); node view `/organisations/:orgId/nodes/:nodeId`.
- **Pools list**: green dot (≥1 node online) or amber (none) with "online / total nodes online", from `Pool.onlineNodes` and `Pool.totalNodes`, refreshed every 10 s.
- **Pool screen**: details, devices (admin-only **Add web node** button `AddWebNodeButton`: creates an enrollment code and opens `https://web-node.<domain>/#code=...` in a new tab (`lib/webNode.ts`, `VITE_WEB_NODE_URL` overrides); admin-only **Add many devices** dialog `BulkEnrollDialog` (1..50 single-use codes, used/unused progress, copy all, CSV, cancels the unused on close); admin-only **Add device** dialog `EnrollDeviceDialog`: code as text and QR with countdown, API address with copy button, cancels the code on close, closes itself when a new node appears), served models, pool-scoped usage, and **Benchmarks** (`PoolBenchmarks`: admin **Run benchmark**, a card per run with each device's tokens/s, first-token and total time and the pool total; polls every 3 s while running).
- **Node view**: status, CPU, memory, load, battery/temperature, device info, approve/revoke, engine card (what the device runs on + admin Select for compute backend device decides/CPU/GPU, numeric max context 512–131072 (empty clears), device decides/on/off selects for MTP and keep-screen-on; saved on change/blur); polls every 10 s.
- **API keys** (admins): cards with status/scope (an **Expiring soon** badge under 7 days left); create dialog (whole org or pool checkboxes, expiry, limits); **Change expiry** dialog per key (30/90/365 days from today or never; also revives an expired key); one-time secret dialog with copy plus **Use this key** (curl and Python OpenAI-client examples with the secret filled in, only in this dialog; base URL `app.<domain>` → `gateway.<domain>` + `/v1`, `VITE_GATEWAY_URL` overrides, `lib/gateway.ts`); per-key **Edit limits**; revoke.
- **Models**: status, download progress, retry, delete, add from a Hugging Face link or upload with part-level progress/retry (`lib/uploadParts.ts`). The add dialog has a **Type** choice (Chat / Embeddings); embedding models show "Embeddings ·" on their card and are left out of the Playground's model picker (`GET /v1/models` entries carry `kind`).
- **Node page**: admin **Restart** button (confirm dialog; disabled unless the node is online): asks the device to finish what it serves and restart its app (`POST .../nodes/:nodeId/restart`).
- **Account settings** (`/user-settings`, private; linked from the user menu, not the sidebar): shows name/email and a danger zone that deletes the account (`DELETE /api/me`, confirm dialog, then drops the local session and returns to `/`). The API refuses while the user is the only owner of an organisation; the error toast carries the org names.
- **Playground** (`/playground`, private; sidebar item and a Home "Test it" card that opens it in a new tab): chat with a pool from the browser. The user **pastes an API key** (held only in component state, never stored or minted); `GET /v1/models` with it fills the model picker, then `POST /v1/chat/completions` streams SSE (`lib/chatStream.ts`; stop aborts the request so the gateway cancels the node). Options: system prompt, temperature, max tokens (empty = default); shows time to first token and tokens/s per reply. **Attachments** (`lib/attachments.ts`): paperclip / drag and drop / paste for images, audio and text files, plus a microphone button (`MediaRecorder`). Images the gateway takes (JPEG/PNG/GIF/BMP ≤ 1 MiB) go as they are, others (WebP, big) are scaled to 1024 px and re-encoded as JPEG; audio the gateway takes (wav/mp3/flac ≤ 5 MiB) goes as it is, any other (recordings, m4a, ogg) is decoded with Web Audio and sent as 16 kHz mono WAV (≤ 10 min); text files (≤ 200 KiB, by mime or extension, no binary) are pasted into the message as a fenced `[File: name]` block; PDFs and other binaries are refused. Sent as OpenAI content parts (`image_url` data URL, `input_audio`); a message without media stays a plain string. The whole conversation, media included, is resent every turn, so the page stops at the gateway's per-request media limit (`max_media_bytes` from `/v1/models`, default 256 MiB). A warning shows when the selected model's `input_modalities` (from `/v1/models`) lacks an attached kind. The node page shows what a node accepts (`live.modalities`). **No chat memory**: the conversation lives in state and is resent in full each turn; refresh clears it. Assistant text rendered with `react-markdown` (no raw HTML). Calls go to **`/v1` on the web app's own origin** (`getPlaygroundBaseUrl`, `VITE_GATEWAY_URL` overrides), which the chart routes to the gateway (`gateway.appIngress`, `templates/gateway-app-ingress.yaml`), so **the gateway has no CORS headers**.
- **Audit log** (`/organisations/:orgId/audit`, admins and owners only; sidebar item and the page redirect plain members): cards newest first with action label (`audit.actions.<action>`, raw action as fallback), time, actor, outcome badge (Gateway badge for gateway events) and one detail line (entity, metadata, ip); filters by category (action prefix) and outcome; **Load more** pages with the cursor (`useAuditLogs`, `useInfiniteQuery`); **Export CSV/JSON** buttons download the filtered log (`useExportAuditLogs`, authenticated fetch to a Blob, `lib/saveFile.ts`). A new action needs its `audit.actions.*` label in en and ro.
- **Rate limits**: three free-text numeric fields (requests/min, tokens/min, tokens/day; empty = unlimited, inline error outside 1..max) in `LimitsFields`: org settings card, key creation dialog, per-key dialog.
- **Page headings and look**: every page uses `components/layout/PageHeader` (eyebrow, title, subtitle, actions; org pages show the org name as eyebrow). No gradients (flat brand colour `#4f5df0`; only the logo asset has one). The shell has a translucent blurred top bar, a short fade-in per route (`.sc-enter` in `index.css`, disabled by `prefers-reduced-motion`) and clickable cards lift with a brand border on hover.
- **Home** is a landing page (`pages/Home.tsx`): hero with an animated `NetworkDiagram` (devices → gateway → your app), trust chips, "how it works" steps, feature cards, a curl example next to the Playground card, **Run a node** (`AppDownloads bare`), **Endpoints** (`Endpoints bare`) and a closing call to action. Signed-out visitors get a "Get started" button that starts the Dex sign-in. **About** (`pages/About.tsx`) is the long story: why, the two-leg request flow, principles, node types. Public pages keep internal plans (roadmap, pricing, what we will not build) and the tech stack (languages, frameworks, protocols) out of the copy; WebGPU and LiteRT-LM (the model format) are named on purpose. Hugging Face appears only where the Models page needs it. Shared pieces live in `components/marketing/`. Copy is in `home.*`/`about.*` (en + ro).
- **Home content**: `components/Endpoints.tsx` two cards with copy buttons: gateway base URL (`getGatewayBaseUrl`, `.../v1`) and control plane API URL (`getApiBaseUrl`: web app origin + `/api`, `VITE_API_URL` overrides). `components/AppDownloads.tsx` ("Run a node", on Home, section `#run`; a pool page only links to `/#run` in a new tab, next to "Add device", and the Home page scrolls to the hash after render): **Mobile app** (Download APK → `releases/tag/mobile-node-latest` new tab; Google Play/App Store buttons inert until listings exist), **Command line** (`curl … install.sh | sh` for Linux/macOS, `irm … install.ps1 | iex` for Windows, each with a copy button, plus a `releases/tag/cli-node-latest` button; scripts fetched from GitHub raw `src/cli-node/install.*`), **Web node** (open in new tab without a code; share via `navigator.share`, else copy link). Each app has its own rolling release (`<stream>-latest`, prerelease, rewritten in place by `.github/workflows/rolling-release.yaml` after every node release), because GitHub release search cannot filter one stream or sort by version.
- **Version**: the sidebar footer shows the **Helm chart version** (`lib/useChartVersion.ts` fetches `/version.json`; Caddy serves it from env `APP_VERSION`, which `ui-deployment.yaml` sets to `.Chart.Version`; the Vite dev server has the same route). Hidden until loaded or if the fetch fails.

## Charts and metrics

Charts use **`@fluentui/react-charts`** (Fluent UI Charting v9, themed by the Fluent tokens; no other chart library), wrapped by `components/charts/TimeCharts.tsx` (`ChartCard`: line or stacked bars, a card per chart). `MetricsView` (`pages/organisations/MetricsView.tsx`) shows **live** charts (refresh every 15 s, a switch freezes them; ranges 15 min to 7 days) at three levels: organisation (page **Metrics**), pool (section on the pool screen) and node (section on the node screen, telemetry only: gateway numbers exist per pool). The device charts include **measured tokens/s** and **failure rate** (from the gateway's own measurements) next to the tokens/s the device reports. Usage (`UsageView`) has request and token charts above its period cards. In tests the chart package is mocked (jsdom has no canvas).

## Container

`Dockerfile` (multi-stage: pnpm test, pnpm build, precompress, Caddy on 8080 with SPA fallback, `/healthz`, non-root; `Caddyfile`), `Dockerfile.dev` (Vite on 8080 for Tilt); chart `ui-deployment/ui-service/ui-ingress.yaml` under `ui:` (ingress on by default at the web app host). **Brotli**: `scripts/precompress.mjs` (Node zlib, quality 11) writes `.br` copies of the compressible files after `pnpm build` and Caddy serves them (`file_server { precompressed br }`); other encodings (zstd, gzip) are done on the fly by `encode`.
