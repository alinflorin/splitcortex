# CLI node (`src/cli-node`)

Rules: [CLAUDE.md](../CLAUDE.md). A **headless, Rust-only node** for Linux, macOS and Windows (the only desktop/server node; no GUI app, decided): enroll with a code, connect out to the gateway, download the pool's model, serve. One binary plus the engine library, installed by a script from this repo.

**Ported code**: `crypto.rs`, `handshake.rs`, `connection.rs`, `enroll.rs`, `models.rs`, `runtime.rs`, `engine/compute.rs` port the web node's TypeScript (`enrollment/crypto.ts`, `protocol/handshake.ts`, `protocol/connection.ts`, `enrollment/client.ts`, `models/manager.ts`, `runtime/NodeRuntime.ts`, `engine/compute.ts`). **A fix in one belongs in the other.** Shared contracts: the protobuf (generated from `src/gateway/proto` by `build.rs`), the enrollment crypto (`src/control-plane/src/enrollment/crypto.ts`), the handshake labels (`src/gateway/src/node_ws.rs`).

## Stack and layout

Rust 2024, `tokio`, `tokio-tungstenite`, `reqwest` (**rustls with OS root certs**, no OpenSSL), `prost` (`build.rs` + `protox`), `curve25519-dalek` + `sha2` (CPace), `ed25519-dalek`, `hkdf`, `chacha20poly1305`, `libloading`, `clap`, `sysinfo`, `keepawake`. Files: `main.rs`, `runtime.rs`, `connection.rs`, `enroll.rs`, `crypto.rs`, `handshake.rs`, `models.rs`, `restart.rs`, `engine/{mod,ffi,compute,embed}.rs`, `storage.rs`, `settings.rs`, `system.rs`, `service.rs`, `update.rs`. Scripts: `fetch-litert.py` (pinned LiteRT-LM v0.19.1 zip + SHA-256), `set-version.py`, `package.py`, `install.sh`, `install.ps1`.

## Commands

`splitcortex-node join [--url <web app>] [--code XXXX-XXXXXX]` (address: `--url`, `SPLITCORTEX_URL`, `settings.json` `appUrl`, else `https://splitcortex.com`; `https://host` and `https://host/api` both work), `run` (foreground; waits for approval if required), `status`, `leave`, `config [--compute auto|cpu|gpu] [--context N] [--keep-awake true|false] [--url ...] [--models-dir /abs/path]`, `update [--check]`, `service install|uninstall|status`. Admin overrides win over `config`, field by field. Platform `cli`. Logs to stderr (`RUST_LOG`), never prompts/completions.

## State and engine

- Data dir (`directories`; `SPLITCORTEX_HOME` overrides): `models/` (**movable**: `config --models-dir <absolute path>` saves it in `settings.json` (`modelsDir`, empty resets), `SPLITCORTEX_MODELS_DIR` wins over it; only the models move, the key and state stay; files already downloaded are not moved (the node downloads again, or move the `<id>.litertlm` and `<id>.ok` files yourself); **one node per models folder**, two nodes downloading the same model into one folder would write the same file; the node only lists and deletes files named `<model uuid>.litertlm|.ok` (`storage::is_model_file`), so a folder with other files in it is safe), `secrets/device-key` (0600, dir 0700; Windows relies on the profile ACL), `enrollment.json`, `settings.json`, `backend-bench.json`. Software Ed25519 key.
- **Engine**: Google's official LiteRT-LM C API (`litert_lm_c_api-1.0.0.zip` of v0.19.1) loaded with `libloading`; `ffi.rs` declares only what is used (no bindgen); never unloaded (`ManuallyDrop`: `dlclose` crashed). `fetch-litert.py` checks the SHA-256; libraries for linux x86_64/arm64, windows x86_64, macOS arm64, **none for macOS x86_64**. Updating = change `VERSION`/`SHA256` and re-check `ffi.rs` against the headers. Library is found in `litert/` next to the executable (symlinks resolved) or via `SPLITCORTEX_LITERT_LIB`. One model, one generation at a time; `create_best` tries media on then off, each with MTP then without. `gpuAvailable` is true on macOS, Windows, and Linux when `libvulkan.so.1` loads (only gates the automatic CPU-vs-GPU measurement). Image/audio: `Engine::modalities()` into `ModelState.modalities`; protocol `parts` are base64-encoded into `engine::Part`s. _Unchecked on hardware_: conversation chunk format, chat-template role names, GPU backends per OS, MTP drafter, multimodal models.
- **Embedding models** (`models.rs` `Kind`, `engine/embed.rs`, `engine/ffi.rs`): loaded into LiteRT-LM's embedding engine (`litert_lm_embedding_engine_*`); loading either kind unloads the other. Dimension from `litert_lm_loaded_file_embedding_dimension`, else a probe. READY with `embedding_dimension`, no modalities, context 0. Backend: `gpu` choice else CPU (failed GPU load falls back); context/MTP don't apply. Per input: trim, EmbeddingGemma prefix by `task` (query `task: search result | query: `, document `title: none | text: `, classification `task: classification | query: `, clustering `task: clustering | query: `, similarity `task: sentence similarity | query: `, empty none), **one batch call** (overflow strategy "error"), truncate + L2-renormalise when `0 < dimensions < full`. One `EmbeddingResult` (seq 1, `prompt_tokens` 0) or `InferenceError` (`bad_input` incl. input over the window, `engine_error`, `model_not_ready`, `wrong_model_kind`, `restarting`). Embeddings queue (no `busy`). NaN/infinity = `engine_error`.
- **Remote restart** (`restart.rs`, `runtime.rs`): new requests get `restarting`; running ones finish up to the grace (embeddings wait 5 s more), then models and connection stop and `runtime::run` returns `End::Restart`. `main` relaunches: **Unix `exec`s the same binary and arguments in place** (same PID, so systemd/launchd see one process; works in a plain terminal; after `update` the new file starts); **Windows** starts a detached process and exits 0. A failed relaunch exits 75. Installed units use `Restart=always` / `KeepAlive`. Fresh state after relaunch.
- One request at a time (`busy`); chunks carry `seq` and stay in an outbox 60 s for `Resume`; running requests given up after 40 s without a gateway.

## Install, service, update

- **Install**: `curl -fsSL https://raw.githubusercontent.com/alinflorin/splitcortex/main/src/cli-node/install.sh | sh` (Linux x64/arm64, macOS arm64), `irm …/install.ps1 | iex` (Windows x64); both shown in the web app's _Command line_ card. The script finds the newest `cli-node-v*` release via the GitHub API (not `releases/latest`), downloads `splitcortex-node-<target>.tar.gz|zip` + `.sha256`, verifies, unpacks into `~/.local/lib/splitcortex-node` (`%LOCALAPPDATA%\Programs\SplitCortexNode`) with a link in `~/.local/bin` (Windows: user PATH). `SPLITCORTEX_VERSION`, `SPLITCORTEX_INSTALL_DIR`, `SPLITCORTEX_BIN_DIR`, `SPLITCORTEX_URL` tune it. It asks for the web app address (via `/dev/tty`; skipped without a terminal) and saves it with `config --url`. Files fetched by `curl`/`irm` carry no quarantine mark, so Gatekeeper/SmartScreen don't block the unsigned binary.
- **Service**: `service install` writes a systemd **user** unit (with `loginctl enable-linger`), a launchd agent, or a logon scheduled task; it runs `splitcortex-node run`.
- **Update**: takes the newest published `cli-node-vX.Y.Z` (no drafts/pre-releases/other streams), verifies the checksum, replaces binary and library in place (Windows moves the running `.exe` to `.old`). Restart afterwards.

## Release and CI

- **Tag `cli-node-vX.Y.Z`** (own stream). `cli-node-release.yaml` creates the release (not latest), builds linux x64 (`ubuntu-22.04`), linux arm64, macOS arm64, Windows x64: `set-version.py`, `fetch-litert.py --required`, `cargo build --release --target`, `package.py` (binary + `litert/<library>`, `.sha256`), `gh release upload`. No secrets.
- **CI** `cli-node.yaml` (path filter includes `src/gateway/proto/**`): `cargo test` on all four platforms, `cargo fmt --check` and `clippy -D warnings` on Linux x64, `shellcheck install.sh`. Release profile: thin LTO, 16 codegen units. Not a deployed service.

## Verified / not

Verified on Linux x64: unit tests, **CPace byte for byte against `@cipherman/pake-js`**, the connection against a fake gateway, a command smoke test, `install.sh` end to end; the owner has run enrollment, a session and generation on real laptops. _Not verified_: a real embedding model, a real remote restart (Unix `exec` and the Windows spawn untested), Windows/macOS beyond CI compilation, `install.ps1`, service install, `update` against a real release.
Not built: macOS Intel, battery/temperature telemetry, hardware-backed key, OS code signing, Docker image.
