# Mobile node (`src/mobile-node`)

Summary in [CLAUDE.md](../CLAUDE.md). The web node ([web-node.md](web-node.md)) ports this app's enrollment, protocol, runtime, compute and model code, so a change here usually needs the same change there. The owner has run the app on real Android devices (details not recorded); items marked *unchecked* were never specifically verified.

## App

- Expo SDK 58, Expo Router (`src/app/`), `expo-dev-client`. **Fluent UI React is DOM-only**, so only `@fluentui/tokens` (`teamsLightTheme`/`teamsDarkTheme`) are reused, read via `useTheme()` (`src/theme/ThemeContext.tsx`; System/Light/Dark, default System, in AsyncStorage) by thin components in `src/components/` (`Text`, `Button`, `Card`, `Screen`, `ChoiceGroup`, `Logo`/`Brand`: the web `logo.svg` redrawn in `react-native-svg` plus the lowercase two-colour Inter wordmark, `#14b8d4` split / `#4f5df0` cortex; keep in sync with the web sidebar). No `@fluentui-react-native` or other component library. Inter bundled via `@expo-google-fonts/inter` (no CDN; weights map to families in `theme/fonts.ts`). i18n: i18next, bundled JSON (`src/i18n/locales`, en + ro; stored choice, then device language, fallback en). Cards, hairline borders, no shadows, strict TS, no `any`.
- Tests: Jest (`jest-expo`, `@testing-library/react-native` 14 with async `render`/`renderHook`/`fireEvent`, setup `src/test/setup.ts` mocks AsyncStorage, `renderWithTheme` in `src/test/render.tsx`), next to code as `*.test.ts(x)`.
- **Enrollment UI** (`src/app/enroll.tsx`, `src/enrollment/`): typed short code (always) or QR (`expo-camera`), editable enrollment URL (control plane, not gateway; default `EXPO_PUBLIC_ENROLLMENT_URL`), deep link `splitcortex://enroll?url=...&code=...`. Protocol: [enrollment.md](enrollment.md).
- **Home**: service card (connection, model + download progress, counts, start/stop/restart; no button opening the web app); lists org, pool, device name/ID, key fingerprint, enrollment time, control plane and gateway URLs (org/pool names from the enrollment response, refreshed from `GET /node/me` in `enrollment/info.ts` when focused, best effort). **Logs** screen: in-memory ring of 500 lines, share/clear, states and counts only, never prompts/completions. **Settings**: Service toggles *start at boot* (default on) and *connect and load the model on start* (default on), Compute, Context, MTP, keep-screen-on; the app version (`expoConfig.version`, from the `mobile-node-vX.Y.Z` tag) is shown under the cards.

## Runtime

- `src/runtime/NodeRuntime.ts` owns the gateway connection (`src/protocol/connection.ts`: wss + protobuf, mutual proof of possession against the key **pinned at enrollment**, never authenticates to a server whose proof doesn't match; jittered reconnect up to 30 s; 60 s idle watchdog; answers pings), the model manager (`src/models/manager.ts`) and the engine (`src/engine`). Proto types are generated (`pnpm gen:proto`, committed under `src/protocol/gen`); handshake bytes in `protocol/handshake.ts` must match `src/gateway/src/node_ws.rs`.
- **Models**: on `ModelAssignment` download from `<enrollment URL>/node/models/<id>/file` in 4 MiB `Range` requests streamed to disk (never a whole body in memory: the Android JS heap is ~192 MB and 8 MiB bodies ran out), each signed with the device key (`Authorization: Node ...`, so the 60 s skew never breaks long downloads), resume from `.part` after restart, verify SHA-256 (native `File.digest`), delete the previous model first (may not fit two), load. Status none/downloading/loading/ready/failed goes to the gateway as `ModelState`; a re-sent assignment of the ready model is only re-reported.
- **Resume / key rotation**: every chunk/done/error is numbered and kept per request (`outbox`, up to 20 000 frames, 60 s after the end); after reconnect send `Resume`, resend above `ResumeAck`, drop ids the gateway doesn't list (and on `Cancel`); give up a running request after 40 s unreachable; foreground return reconnects at once (`reconnectNow`). Trusts the pinned gateway key plus keys announced during a rotation (signed by a trusted key over the connection nonce, stored in `gateway.nextKeys`); a proven next key becomes current. Reports trusted key ids (`GatewayKeys`) after every `Ready`.

## Engine

- `Engine` interface (`src/engine/types.ts`); adapter `LiteRtEngine` over third-party **`react-native-litert-lm`** (Nitro module; not official: read its code before relying on it; its postinstall only fetches the iOS framework, so the pnpm build script stays unapproved while iOS isn't built). Required lazily (without the native build the app runs and requests fail clearly). Each OpenAI request is self-contained: history flattened to a system prompt plus one user turn; sampling/system changes reload the model. One request at a time. **Image/audio input**: only the last user turn's media is sent (the library takes buffers: `{type:'image', imageBuffer}` / `{type:'audio', audioBuffer}` after the text; earlier turns show `[Image]`/`[Audio]` in the transcript); what the model accepts comes from the bundle's metadata (`getModelInfo().modalities.vision/audio`) and is reported in `ModelState.modalities`. Not run on a device yet. Other wrappers exist (`expo-litert-lm`, `expo-ai-kit`), none official.
- **Compute and context** (`engine/compute.ts`, `ComputeEngine`), decided **per field: admin override (`NodeConfig`) > app setting > automatic**. Settings: Compute Auto/CPU/GPU; Context a number 512–131072 (empty = auto; saved on blur since every change reloads). Automatic backend: with a GPU driver (`getDeviceInfo().gpuAvailable`) and not an emulator, the first load of a model file benchmarks both (40 decode tokens), takes GPU only if >10 % faster (`GPU_MARGIN`), remembers per model file in AsyncStorage; else CPU. Automatic context by RAM (<4 GB: 2048, <10 GB: 4096, else 8192; unknown: library default 4096). Forced GPU without a driver runs on CPU; a failing load steps back (requested → CPU → CPU default window). Effective-setting changes reload the model after a running generation finishes; requests wait. Backend and window are shown on Home and sent in `Telemetry.backend`/`max_context_tokens` (also after load/reload) for context-aware routing. The bundle's compiled cache length isn't read yet.
- **MTP** passes `enableSpeculativeDecoding` (bundle's drafter, e.g. Gemma 4; ignored without one; a failed load retries without it). **Keep screen on** sets `FLAG_KEEP_SCREEN_ON` through the native module (some devices run the GPU at full speed only with the display on); re-applied on foreground, cleared when the service stops. Both are tri-state admin overrides (`NodeConfig`; empty = device's own).
- **Telemetry** (native `getTelemetry()`): this app's CPU share of the device (Android blocks other apps' CPU), app PSS memory (includes the mapped model), battery %, charging, battery temperature; sent every 10 s with tokens/sec, unknown = protocol sentinels. No iOS equivalent. CPU core count has no JS API, so enrollment sends no `cpuCores` (would need a tiny native module).

## Android

- **Background service** (`modules/splitcortex-node-service`, local Expo module, Kotlin, autolinked): `NodeService` is a foreground service of type `specialUse` (`dataSync` can't start from boot on Android 15; a boot receiver can't start an activity) with partial wake lock and an ongoing low-priority notification, extending `HeadlessJsTaskService` to run the JS task `SplitCortexNode` with no UI. `BootReceiver` starts it on `BOOT_COMPLETED` and after app update when *start at boot* is on (mirrored into native SharedPreferences, default on, since no JS runs before the receiver). Headless task `src/runtime/headless.ts` (registered from custom entry `index.ts`, since no screen renders after boot) calls `runtime.start()` and stays pending until the runtime stops; it stops the service at once if *connect and load on start* is off or the device isn't enrolled/approved. Same JS runtime and singleton runtime when the app is opened (`start()` idempotent). `runtime.start()/stop()` start/stop the service, so notification and wake lock exist exactly while serving. Android 13+: asks for notification permission (service runs without it, notification hidden).
- **Doze**: also a Wi-Fi lock (`WIFI_MODE_FULL_LOW_LATENCY`, high-perf before Android 10); the app asks to be exempted from battery optimisation (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`; native `isIgnoringBatteryOptimizations`/`requestIgnoreBatteryOptimizations` open the system dialog, falling back to the settings list). `BatteryExemption` card on Home (until exempt) and Settings (always) re-reads on return. Needs user consent. *Unchecked*: boot start after a real reboot, exemption keeping the connection alive screen-off, manufacturer task killers, headless and foreground JS being the same runtime.
- **Build requirements (found by building)**: `react-native-litert-lm` needs **minSdk 26** and its AAR has **Kotlin metadata 2.4.0** while Expo 58 / RN 0.88 default to Kotlin 2.2.0; `app.json` uses `expo-build-properties` with `minSdkVersion: 26`, `kotlinVersion: "2.4.0"` (applied by `expo prebuild`; whole app compiles with Kotlin 2.4). `./gradlew :app:assembleDebug` works (~22 min cold, four ABIs). Android < 8 unsupported. **Build speed**: `react-native-litert-lm` only ships arm64-v8a and x86_64, so the CI release builds just those (`-PreactNativeArchitectures=arm64-v8a,x86_64`) and other CI runs x86_64 only; plugin `plugins/withGradleSpeed.js` sets `org.gradle.jvmargs` (4 GB heap, 1 GB Metaspace: the default 512 MB killed the daemon during R8, ~80 s lost) and `org.gradle.caching`; `verify` and `android` jobs run in parallel. A release was ~23 min of Gradle before these (not re-measured since).
- **x86_64 emulator**: the library hard-codes `abiFilters 'arm64-v8a'`; `patches/react-native-litert-lm.patch` (pnpm `patchedDependencies`) makes the filter follow `reactNativeArchitectures` (arm64-v8a/x86_64) and lets `LiteRTLMPackage` init on an x86_64 primary ABI. After changing the patch delete `android/build/generated/autolinking`. Builds; the engine was not run on an emulator.
- **Backup disabled** (`android.allowBackup: false` in `app.json`) so the device key and enrollment state never restore onto another device (CodeQL alert; `expo-secure-store` also excludes its data).

## iOS (direction only, nothing built or run)

Stays cross-platform: engine, service and device-info interfaces must not assume Android. **Foreground-only**: no foreground service, iOS suspends the app shortly after it leaves the foreground (closing the socket), so it serves only while open with the screen on (idle timer disabled), ideally charging. No audio/VoIP/location tricks (App Store rejection). LiteRT-LM's Swift API (SwiftPM, Metal) is **Early Preview**: re-check before building. Jetsam kills memory-heavy apps. Secure Enclave only supports P-256, not Ed25519: **decided: identity stays Ed25519 in `expo-secure-store`** (software, exportable on a rooted device). Switching to ECDSA P-256 (non-exportable keys on Android/iOS) would change enrollment and re-enroll every node; revisit only if hardware-backed keys become a requirement.

## Setup rules

Dev setup only: physical device, **no EAS**, local builds (`expo prebuild` / `expo run:android|ios`); no Expo Go (native module). The TLS connection to the gateway must stay alive while serving (OS background limits are a known risk). A foreground-service library (Notifee, `react-native-background-actions`) would need testing for keeping a JS WebSocket alive screen-off if the built module is replaced.
