# Commands, CI/CD and releases

Summary in [CLAUDE.md](../CLAUDE.md).

## Chart and Tilt

- `helm lint chart --strict [-f chart/values-stg.yaml]`, `helm template` with the same flags. Local install (`--wait` required so ClusterIssuer hooks run after the cert-manager webhook is ready): `helm upgrade -i --wait --timeout 5m --create-namespace -n splitcortex -f chart/values-local.yaml splitcortex chart`.
- `tilt up` at the root (k3s context `default`, registry `localhost:5000` mirrored in k3s `registries.yaml`). The infra chart installs as a `chart` local_resource via `helm upgrade -i --wait` (not tilt's `helm()`, because of the ClusterIssuer hooks) with app workloads disabled (`--set ui.enabled=false --set controlPlane.enabled=false --set webNode.enabled=false --set gateway.enabled=false`). Each service has `docker_build` + `k8s_yaml(local('helm template ... --show-only templates/<svc>-*.yaml'))`. Wired: `ui`, `web-node`, `control-plane` (+ Job `control-plane-migrate`), `gateway` (dev image runs `cargo watch`; first build takes minutes).
- Gateway scaling: `--set gateway.replicas=3`. Key rotation, one `helm upgrade` per stage: `--set gateway.rotation.stage=prepare`; `kubectl exec deploy/gateway -- gateway rotation-status` until safe; `promote`; then upgrade once more with the stage empty. Each stage restarts gateways and control plane.

## Per-project commands

- **ui** (`src/ui`): `pnpm install`, `pnpm dev` (Vite :5173; open as `http://app.splitcortex.127.0.0.1.nip.io:5173` so Dex URL and redirect URI match), `pnpm build` (`tsc -b && vite build`), `typecheck`, `test` / `test:watch`, `format` / `format:check`. Prettier config in root `.prettierrc` (single quotes, semicolons, width 100, trailing commas) + `.prettierignore` + `.editorconfig` (UTF-8, LF, 2 spaces). Run `pnpm format` before committing.
- **web-node**: same as ui (`pnpm dev` on :5174) plus `pnpm gen:proto` (needs `protoc`; commit the result). CI `web-node.yaml`.
- **control-plane**: `pnpm install`, `dev` (tsx watch, needs `DATABASE_URL`, `OIDC_ISSUER`), `test`, `typecheck`, `build` (tsup), `db:generate` (no DB needed), `db:migrate`, `format`. CI `control-plane.yaml`.
- **gateway** (Rust; proto in `src/gateway/proto`): `cargo build|test|fmt` (`rustfmt.toml`, width 120), `cargo run -- keygen`, `cargo run` (needs `DATABASE_URL`, `GATEWAY_PRIVATE_KEY`). CI `gateway.yaml` builds the image only (the Dockerfile doesn't run `cargo test`; run it locally).
- **mobile-node**: `pnpm install`, `typecheck`, `test`, `format[:check]`, `pnpm exec expo export --platform android` (bundle check), `expo prebuild` then `expo run:android|ios` (local dev build), `pnpm exec expo install <pkg>` to add Expo packages, `pnpm gen:proto`.
- **desktop-node**: `pnpm install`, `dev` (Vite :5175, web side only), `litert:fetch`, `tauri dev|build`, `typecheck`, `test`, `format[:check]`, `gen:proto`; Rust in `src-tauri`: `cargo fmt|clippy|test`. CI `desktop-node.yaml`. See [desktop-node.md](desktop-node.md).
- **cli-node** (Rust only): `python3 scripts/fetch-litert.py`, `cargo build [--release]`, `cargo fmt|clippy --all-targets -- -D warnings|test`, `cargo run -- <command>` (`SPLITCORTEX_HOME=<dir>` separates a test run's state). CI `cli-node.yaml`. See [cli-node.md](cli-node.md).

## CI/CD

- **Images**: reusable `.github/workflows/docker-service.yaml` (`workflow_call`: `service`, `context`, `dockerfile`) builds each arch natively in parallel (amd64 on `ubuntu-latest`, arm64 on `ubuntu-24.04-arm`, no QEMU), pushes by digest to `ghcr.io/<owner>/splitcortex-<service>`, and a `merge` job makes the multi-arch manifest (`docker buildx imagetools create`). GHA cache per service+platform. PRs build only. Tags: `vX.Y.Z` → `X.Y.Z` and `X.Y` (no `v`, = chart `appVersion`); branches/manual → `<branch>`, `sha-<short>`. Each service has a thin caller workflow (path-filtered push/PR, manual, `workflow_call`; no tag trigger); a new service adds one.
- **Chart**: `chart.yaml` lints (`--strict`), renders and kubeconform-validates dev/stg/prd on PRs and pushes to main; on a `vX.Y.Z` tag packages and pushes to `oci://ghcr.io/<owner>/charts`. Dependencies and kubeconform cached with `actions/cache` (keyed on `Chart.yaml`/`Chart.lock`). Keep action versions on the latest major (actions are pinned to commit SHAs).
- **Deploy**: `deploy.yaml` (`workflow_call` + `workflow_dispatch`, inputs `environment` stg/prd, `version`) checks out the tag, substitutes `LETSENCRYPT_EMAIL` into `values-<env>.yaml`, runs `helm upgrade -i --wait --atomic` from `oci://ghcr.io/<owner>/charts/splitcortex`. GitHub environment of the same name holds secrets `KUBECONFIG` (plain or base64), `LETSENCRYPT_EMAIL`, `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`; the stg Dex user for [e2e tests](e2e.md) comes from the repository secrets `E2E_EMAIL`/`E2E_PASSWORD` (the deploy hashes the password); add required reviewers on `prd`. prd is manual only; run manually to redeploy or roll back. Cluster must be reachable from GitHub runners; GHCR packages must be public or an imagePullSecret added (not wired).
- **Wiki**: `wiki.yaml` (push to `main` touching `README.md`/`docs/**`, or manual) runs `scripts/sync-wiki.sh`, which mirrors `README.md` as `Home` and `docs/*.md` as pages into the GitHub wiki repo, rewrites sibling doc links to wiki page links and other relative links to absolute blob URLs, and regenerates `_Sidebar.md` from each doc's H1. One way: **never edit the wiki in the UI** (overwritten). Needs the wiki enabled and its first page (`Home`) created by hand once; uses `GITHUB_TOKEN`, no secrets.
- DB migrations must be expand/contract: `helm --atomic` rolls the app back but not the schema.

- **E2E**: `e2e.yaml` (nightly + manual, repository secrets, no environment), see [e2e.md](e2e.md).

## Releases (decided: independent tag streams, tags by hand, no release-please, no rc tags, the same build is promoted stg → prd)

- **Creating the tags**: by hand, or run the manual workflow `create-tags.yaml` (Actions → Create release tags): version `X.Y.Z` plus checkboxes platform / mobile / desktop / cli, all ticked by default; it pushes the tags one by one from the head of the chosen branch (main). It needs the repository secret `RELEASE_TAG_TOKEN` (personal access token, Contents read/write), because tags pushed with `GITHUB_TOKEN` do not start the release workflows.
- **Server `vX.Y.Z`** (lockstep chart/ui/control-plane/gateway/web-node): `release.yaml` is the only entry (tag filter `v[0-9]+.[0-9]+.[0-9]+`). Calls `chart.yaml` and every service workflow in parallel, creates the GitHub release (generated notes, **latest**), then `deploy.yaml` for stg once all succeed (a new service needs a job and entries in `github-release`'s and `deploy-stg`'s `needs`). Chart version, `appVersion` and image tags = tag without `v`.
- **Mobile `mobile-node-vX.Y.Z`**: `mobile-node-release.yaml` calls `mobile-node.yaml` (no tag trigger of its own), creates the release (not latest) with `splitcortex-mobile-node-vX.Y.Z.apk`. Version/`versionCode` from the tag (CI sets `APP_VERSION`; `app.config.ts` derives `versionCode` = X*10000+Y*100+Z, so minor and patch ≤ 99). Tags build a **signed release APK** (`assembleRelease`) from secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` (create with `src/mobile-node/scripts/create-keystore.sh [--upload]`; **back up the keystore; losing it means installed apps can never update; never commit it**), read by `plugins/withReleaseSigning.js` (without them: debug key). Non-tag builds: debug APKs named after the commit. `mobile-node.yaml` job `verify` (typecheck, format check, Jest, Android `expo export`) and `android` (prebuild + `assembleDebug`, APK artifact 14 days). iOS not built in CI. Protocol compatibility: the gateway should support current and previous protocol version with a minimum app version at connect (not built).
- **Desktop `desktop-node-vX.Y.Z`**: `desktop-node-release.yaml`; details in [desktop-node.md](desktop-node.md). Secrets `DESKTOP_NODE_SIGNING_PRIVATE_KEY[_PASSWORD]`.
- **CLI `cli-node-vX.Y.Z`**: `cli-node-release.yaml` builds linux x64/arm64, macOS arm64, windows x64 (`cargo build --release`, library packed by `scripts/package.py`), uploads `splitcortex-node-<target>.tar.gz|zip` + `.sha256`. Version = tag (`scripts/set-version.py`). `install.sh`/`install.ps1` and `splitcortex-node update` read the newest `cli-node-v*` release. No secrets. Details: [cli-node.md](cli-node.md).
- **Push tags one at a time** (a separate `git push origin <tag>`, seconds apart): GitHub fires no tag workflows when more than 3 tags arrive in one push (happened with 1.3.0).
