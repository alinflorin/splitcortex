# Web node (`src/web-node`)

Summary in [CLAUDE.md](../CLAUDE.md). A **browser tab that serves inference like a phone node**: static web app (own pnpm project, same stack as `src/ui`) at `web-node.<domain>`. It speaks exactly the phone node's protocols, so the control plane and gateway have no special case (only `platform: "web"` in enrollment device info). Run in real browsers against a real model by the owner (browsers, speeds, defects not recorded); unit tests use a fake engine module.

- **Flow**: like the other nodes. An admin creates a code with **Add device** on a pool and types it in or scans the QR (**Scan QR code** in the join card: `components/QrScanner.tsx` opens the rear camera with `getUserMedia`, decodes frames with the bundled `jsqr` every ~150 ms, and `codeFromScan` in `enrollment/link.ts` takes the code from the `splitcortex://enroll?…&code=…` link or a bare code; the link's URL is ignored because this page always enrolls against its own origin; other QRs are ignored; needs HTTPS and camera permission, else a message asks to type the code; the camera stops on unmount; nothing is uploaded) (the page also accepts `https://web-node.<domain>/#code=XXXX-XXXXXX`, read once from the fragment and removed from the address bar; the web app no longer links to it). The web app's `AppDownloads` has **Open web node** (new tab, no code) and **Share link** (`navigator.share`, else copy); host derived `app.` → `web-node.` (`ui/src/lib/webNode.ts`, `VITE_WEB_NODE_URL` overrides). Enrollment, approval and key pinning as in [enrollment.md](enrollment.md).
- **Same origin, no CORS**: the web node host also routes `/api` to the control plane (`controlPlane.ingress` lists it next to `app.<domain>`), so enrollment, `GET /api/node/me` and model downloads use its own origin. Enrollment URL = `<origin>/api` (not editable; `VITE_ENROLLMENT_URL` for standalone `pnpm dev`). The control plane has no CORS code and must not get any. The gateway wss URL comes from enrollment (cross-origin WebSocket needs no CORS; the gateway ignores `Origin`).
- **Ported, not shared** (keep in sync by hand with `src/mobile-node/src`): `enrollment/` (CPace over `@cipherman/pake-js`, sealed request, Ed25519 identity), `protocol/` (handshake bytes must match `src/gateway/src/node_ws.rs`; `src/protocol/gen` from `pnpm gen:proto`, needs `protoc`, committed, prettier-ignored), `runtime/NodeRuntime.ts`, `engine/compute.ts` (admin override > page setting > automatic; automatic backend measures CPU vs WebGPU once per model, context follows `navigator.deviceMemory`), `models/manager.ts`.
- **Identity**: Ed25519 key in the origin's `localStorage` (software key, readable by script on this origin; clearing site data forgets it: re-join and remove the old node in the web app). No hardware keys. Enrollment record also in `localStorage`.
- **Models**: downloaded from the control plane in signed 8 MiB `Range` requests into the **Origin Private File System**, written in place at an offset by a worker (`files.worker.ts`: OPFS synchronous handles exist only in workers; also computes SHA-256 off the main thread). Resumes after reload. Completion = `<modelId>.ok` marker written after the checksum matches (a data file without it is partial). Previous model deleted first. The engine gets a lazily read `File`, never one big buffer. Interface `ModelFiles` (tests use in-memory).
- **Engine** (`engine/litert.ts`): Google's **LiteRT-LM JavaScript API** (`@litert-lm/core`, WASM + WebGPU, **early preview**) behind `Engine`, imported lazily. **Its default WASM path is a jsDelivr URL; never use it**: `vite.config.ts` copies the package's `wasm/` into `/litertlm/` (dev middleware and build output) and the adapter calls `loadLiteRtLm('<origin>/litertlm/')`. Each request is a fresh conversation (`preface.messages` = history, last turn streamed; sampler and output limit in `sessionConfig`). No MTP on the web (admin value ignored). **Image/audio input**: `load` first creates the engine with `visionBackend`/`audioBackend` (same backend as the model, `maxNumImages` 8) and, if that throws (text-only model, not enough memory), again without; `Engine.modalities` (`image`,`audio` or none) goes out in `ModelState.modalities` when READY. Messages with media are sent as typed parts (`{type:'image'|'audio', data: Uint8Array}`; the runtime sniffs the format). Not verified on a real multimodal `.litertlm` yet; a text-only model that loads with encoders anyway would advertise input it cannot process (the request then fails with a node error). Open points: which `.litertlm` files load on the web (the LiteRT-LM web collection ships separate "web" files; an Android file may fail and show as a failed model), practical model size limit (WASM32, 4 GB address space, docs mention up to 2 GB for some builds), threaded WASM (needs cross-origin isolation, not enabled).
- **Foreground only (like iOS)**: no background service; a hidden tab may be throttled/frozen. The page asks to keep the tab open, requests a **Screen Wake Lock** while serving (setting _keep the screen on_, admin wins), reconnects at once when the tab becomes visible or the network returns, and resumes serving when reopened (_connect and load the model when this page opens_). One node per browser profile.
- **Telemetry**: memory = tab JS heap (Chromium only; model WASM memory not counted), battery/charging from the Battery API where it exists, CPU and temperature unknown (sentinels).
- **Version**: the top bar shows the **Helm chart version** next to the name (same `/version.json` mechanism as the web app; `APP_VERSION` set from `.Chart.Version` in `web-node-deployment.yaml`). `VITE_APP_VERSION` (reported to the gateway) is the release version, baked in at build from the `APP_VERSION` build arg that `docker-service.yaml` sets from the tag (`web` outside a tag build).
- **UI**: one page, no router: join card (when not enrolled), node card (status, model, download progress, start/stop/restart, remove this device), settings (compute auto/CPU/GPU, context window, keep screen on, connect on start), logs (states and counts only). No OPFS/workers = error; no WebGPU = warning (CPU only).
- **Deploy**: `Dockerfile` (tests, build, Caddy on 8080, `/healthz`, non-root; `/litertlm/*` is `no-cache` because glue JS and WASM must match), `Dockerfile.dev` (Vite on 8080), chart `web-node-{deployment,service,ingress}.yaml` under `webNode:` (stg/prd override image and host; TLS Secret `web-node-tls` is issued via the web node's Ingress and shared with the control plane's `/api` rule on that host), Tilt resource `web-node`, CI `web-node.yaml` (part of the `vX.Y.Z` release, lockstep). Image ≈ 120 MB of WASM on top of the app.
- **Commands**: `pnpm install`, `dev` (:5174; standalone needs `VITE_ENROLLMENT_URL`), `build`, `typecheck`, `test`, `format` (generated proto ignored via root `.prettierignore`), `gen:proto`.
