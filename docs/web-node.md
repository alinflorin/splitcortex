# Web node (`src/web-node`)

Rules: [CLAUDE.md](../CLAUDE.md). A **browser tab that serves inference like a phone node**: static app (own pnpm project, same stack as `src/ui`) at `web-node.<domain>`. Same protocols as the phone node, so control plane and gateway have no special case (only `platform: "web"`). Unit tests use a fake engine.

- **Enrollment**: admin creates a code with **Add device**; user types it or scans the QR (`components/QrScanner.tsx`: rear camera via `getUserMedia`, frames decoded ~every 150 ms by bundled `jsqr`, nothing uploaded; `codeFromScan` in `enrollment/link.ts` takes the code from a `splitcortex://enroll?…&code=…` link or bare code and ignores the link's URL, since this page always enrolls against its own origin; needs HTTPS + camera permission). `https://web-node.<domain>/#code=XXXX-XXXXXX` is read once and removed from the address bar, though nothing links to it. The web app's `AppDownloads` has **Open web node** and **Share link** (`ui/src/lib/webNode.ts`, `VITE_WEB_NODE_URL`). [enrollment.md](enrollment.md).
- **Same origin, no CORS**: the web node host also routes `/api` to the control plane (`controlPlane.ingress`), so enrollment, `GET /api/node/me` and downloads use the page's origin (enrollment URL `<origin>/api`, not editable; `VITE_ENROLLMENT_URL` for standalone `pnpm dev`). The control plane has no CORS code and must not get any. A cross-origin WebSocket to the gateway needs none (gateway ignores `Origin`).
- **Ported, not shared** (keep in sync by hand with `src/mobile-node/src` and the CLI): `enrollment/`, `protocol/` (handshake bytes must match `gateway/src/node_ws.rs`; `src/protocol/gen` from `pnpm gen:proto`, committed, prettier-ignored), `runtime/NodeRuntime.ts`, `engine/compute.ts` (admin > page setting > automatic; backend measures CPU vs WebGPU once per model, context follows `navigator.deviceMemory`), `models/manager.ts`.
- **Identity**: Ed25519 key + enrollment record in the origin's `localStorage` (clearing site data forgets it: re-join and remove the old node).
- **Models**: downloaded from the control plane in signed 8 MiB `Range` requests into the **Origin Private File System**, written at an offset by a worker (`files.worker.ts`: OPFS sync handles exist only in workers; also SHA-256). Resumes after reload. Done = `<modelId>.ok` written after the checksum matches. Previous model deleted first. Engine gets a lazily read `File`. Interface `ModelFiles` (tests use memory).
- **Engine** (`engine/litert.ts`): Google's **LiteRT-LM JS API** (`@litert-lm/core`, WASM + WebGPU, early preview) behind `Engine`, imported lazily. **Its default WASM path is a jsDelivr URL: never use it**: `vite.config.ts` copies the package's `wasm/` to `/litertlm/` and the adapter calls `loadLiteRtLm('<origin>/litertlm/')`. Each request is a fresh conversation (history in `preface.messages`). No MTP. **Image/audio**: `load` first creates the engine with `visionBackend`/`audioBackend` (same backend, `maxNumImages` 8), retrying without on throw; `Engine.modalities` goes out in `ModelState`; media as typed parts (`{type, data: Uint8Array}`). Limits: separate "web" `.litertlm` files, WASM32 size (~2–4 GB), no threaded WASM (no cross-origin isolation).
- **Embeddings** (`kind == "embedding"`): `Embedder` (`engine/litert-embedder.ts` over `EmbeddingEngine`, same self-served WASM, **CPU only**: on WebGPU EmbeddingGemma gives NaN or finite-but-wrong vectors), `inputOverflowStrategy: ERROR`, asks for 8192 input tokens and on "exceeds maximum available signature length (N)" retries with N (community file: 512). `ModelManager` unloads the other kind first and treats a missing `kind` as chat. READY reports `embedding_dimension` (probed after load). `engine/embedding.ts` trims, writes the prefix and truncates + renormalises `dimensions`. One `EmbeddingResult` (seq 1, `prompt_tokens` = summed `inputLength`). Errors: `bad_request`, `engine_error`, `model_not_ready`, `wrong_model_kind`. **NaN gotcha**: with default `minInputLength` = `maxInputLength` (one signature) EmbeddingGemma returns NaN for every input, so the adapter also prepares a shorter signature (`minInputLength` 64); the load probe checks the numbers and NaN is never returned. The WASM engine doesn't enforce the window (it chunks), so the adapter compares `inputLength` with it and answers `bad_request`.
- **Remote restart**: `NodeRuntime.restartApp` refuses new requests (`restarting`), waits for running ones up to grace (then aborts), `stop()` and `Host.restartApp()` (reloads the tab). A `sessionStorage` flag makes the reloaded page serve even if "connect on start" is off.
- **Foreground only**: a hidden tab may be throttled. Requests a **Screen Wake Lock** while serving (admin wins), reconnects when the tab becomes visible or the network returns. One node per browser profile.
- **Telemetry**: tab JS heap (Chromium), battery where available; CPU and temperature unknown.
- **Version**: top bar shows the **chart version** (`/version.json`, env `APP_VERSION`). `VITE_APP_VERSION` (reported to the gateway) is the release version from the `APP_VERSION` build arg (`web` outside tag builds).
- **UI**: one page, no router: join card, node card (status, model, progress, start/stop/restart, remove), settings (compute, context, keep screen on, connect on start), logs (states and counts only). No OPFS/workers = error; no WebGPU = warning.
- **Deploy**: `Dockerfile` (tests, build, Brotli precompress, Caddy on 8080, `/healthz`, non-root; `/litertlm/*` `no-cache` because glue JS and WASM must match; `X-Robots-Tag: noindex` everywhere and `Disallow: /`), `Dockerfile.dev`, chart `web-node-*.yaml` under `webNode:` (TLS Secret `web-node-tls`, shared with the control plane's `/api` rule on that host), Tilt `web-node`, CI `web-node.yaml` (lockstep `vX.Y.Z`). Image carries ~120 MB of WASM. **Analytics**: same banner and GA stream setup as the web app (prod only, after consent; [ui.md](ui.md#analytics)); `/config.json` served by its Caddy from `GA_MEASUREMENT_ID`.
- **Commands**: `pnpm install`, `dev` (:5174), `build`, `typecheck`, `test`, `format`, `gen:proto`.
