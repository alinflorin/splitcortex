# Web node (`src/web-node`) details

Summary in [CLAUDE.md](../CLAUDE.md).

A **browser tab that serves inference like a phone node**: a static web app (own pnpm project, same stack as `src/ui`: Vite, React + React Compiler, TypeScript strict, Fluent UI, react-hook-form + zod, react-i18next en + ro, Vitest, self-hosted Inter, no CDNs, cards). Served at `web-node.<domain>`. It speaks exactly the phone node's protocols, so the control plane and the gateway have no special case for it (only `platform: "web"` in the enrollment device info).

- **Flow**: in the web app, a pool's devices section has **Add web node** (admins). It creates an enrollment code like **Add device**, then opens `https://web-node.<domain>/#code=XXXX-XXXXXX` in a new tab (`ui/src/pages/organisations/AddWebNodeButton.tsx`, `ui/src/lib/webNode.ts`; the host derives from `app.` to `web-node.`, `VITE_WEB_NODE_URL` overrides; the tab is opened on the click and pointed at the link when the code exists, so popup blockers allow it, and if blocked the current tab goes there). The code is in the **URL fragment** (never sent to a server, so not in access logs or `Referer`); the page reads it once and removes it from the address bar. The code is prefilled, the user still presses **Join** (typing the code works too). Enrollment, approval and the pinned gateway key are identical to the phone ([enrollment.md](enrollment.md)).
- **Same origin, no CORS**: the web node's ingress host also routes `/api` to the control plane (`controlPlane.ingress` lists `web-node.<domain>` next to `app.<domain>`), so the browser enrolls, calls `GET /api/node/me` and downloads models from its own origin. The enrollment URL is `<origin>/api` (not editable; `VITE_ENROLLMENT_URL` overrides it for a standalone `pnpm dev`). The control plane has no CORS code and must not get any for this. The gateway wss URL comes from enrollment (cross-origin WebSocket, no CORS; the gateway does not check `Origin`).
- **Ported, not shared** (like the UI, no shared package; keep in sync by hand with `src/mobile-node/src`): `enrollment/` (CPace over `@cipherman/pake-js`, sealed request, Ed25519 identity), `protocol/` (handshake bytes must match `src/gateway/src/node_ws.rs`; `src/protocol/gen` is generated from `src/gateway/proto` with `pnpm gen:proto`, needs `protoc`, committed, prettier-ignored), `runtime/NodeRuntime.ts` (connection, resume outbox, telemetry, admin `NodeConfig`), `engine/compute.ts` (admin override > this page's setting > automatic; automatic backend measures CPU against WebGPU once per model and context follows `navigator.deviceMemory`), `models/manager.ts`.
- **Identity**: Ed25519 key in this origin's `localStorage` (software key, like the phone's; readable by script on this origin; clearing site data forgets it, then the device must join again and the old node is removed in the web app). No hardware keys. Enrollment record also in `localStorage`.
- **Models** (`models/`): downloaded from the control plane in signed 8 MiB `Range` requests into the **Origin Private File System**, in place at an offset through a worker (`files.worker.ts`, OPFS synchronous access handles exist only in workers; it also computes the SHA-256 off the main thread). A download resumes after a reload. Completion is a `<modelId>.ok` marker written after the checksum matched; a data file without it is partial. The previous model is deleted first (replace). The engine gets the stored file as a lazily read `File`, never as one big buffer. The storage interface is `ModelFiles` (tests use an in-memory one).
- **Engine** (`engine/litert.ts`): Google's **LiteRT-LM JavaScript API** (`@litert-lm/core`, WASM + WebGPU, **early preview**) behind the same `Engine` interface. Imported lazily. **The package's default WASM path is a jsDelivr URL; we never use it**: `vite.config.ts` copies the package's `wasm/` into `/litertlm/` (dev middleware and build output) and the adapter calls `loadLiteRtLm('<origin>/litertlm/')`. Each request is a fresh conversation (`preface.messages` = the history, the last turn is streamed; sampler and output limit in `sessionConfig`). Multi-token prediction is not available on the web (the admin value is ignored). **Not run in a real browser against a real model yet**; unit tests use a fake module. Open points to check there: which `.litertlm` files load on the web (the LiteRT-LM web collection ships separate "web" files; an Android file may fail to load and then shows as a failed model), the practical model size limit (WASM32, 4 GB address space, the docs mention up to 2 GB for some builds), threaded WASM (needs cross-origin isolation, not enabled).
- **Foreground only (like iOS)**: there is no background service. A hidden tab may be throttled or frozen by the browser; the page asks to keep the tab open, requests a **Screen Wake Lock** while serving (setting *keep the screen on*, admin override wins) and reconnects at once when the tab becomes visible or the network returns. A node that was serving resumes when the page opens again (*connect and load the model when this page opens*). One node per browser profile.
- **Telemetry**: memory = JS heap of the tab (Chromium only; the model's WASM memory is not counted), battery and charging from the Battery API where it exists, CPU and temperature unknown (protocol sentinels).
- **UI**: one page, no router: join card (when not enrolled), node card (status, model, download progress, start/stop/restart, remove this device), settings (compute auto/CPU/GPU, context window, keep screen on, connect on start), logs (states and counts only, never prompts or completions). Unsupported browsers (no OPFS/workers) get an error, no WebGPU a warning (CPU only).
- **Deploy**: `Dockerfile` (tests, build, Caddy on 8080, `/healthz`, non-root; `/litertlm/*` is `no-cache` because the glue JS and the WASM must always match), `Dockerfile.dev` (Vite on 8080), chart `web-node-{deployment,service,ingress}.yaml` under `webNode:` (stg/prd override image and host; the TLS Secret `web-node-tls` is issued through the web node's Ingress and shared with the control plane's `/api` rule on that host), Tilt resource `web-node`, CI `.github/workflows/web-node.yaml` (part of the `vX.Y.Z` server release, lockstep). The image is about 120 MB of WASM on top of the app.
- **Commands** (in `src/web-node`): `pnpm install`, `pnpm dev` (Vite on :5174; standalone it needs `VITE_ENROLLMENT_URL` pointing at a control plane), `pnpm build`, `pnpm typecheck`, `pnpm test`, `pnpm format` (ignores the generated proto through the root `.prettierignore`), `pnpm gen:proto`.
